# Project Overview: Revision Hub

## Description
Revision Hub is a statically generated, premium study portal designed with a sleek, high-end "Black Glass" aesthetic. It centralizes syllabus-aligned question banks, midterm study guides, and high-yield cheat sheets across multiple university subjects. The interface is meticulously crafted to be distraction-free for high-pressure, late-night study sessions.

## Supported Subjects & Color Identity
Every subject is tied to a distinct, unique `--subject-color` CSS variable that drives the UI's ambient glows, custom checkboxes, gradient headings, topbar title, and FAB button:
1. **DBMS** (Database Management Systems) – Blue `#3b82f6`
2. **Java** (Object Oriented Programming) – Orange `#f97316`
3. **OS** (Operating Systems) – Emerald `#10b981`
4. **DAA** (Design and Analysis of Algorithms) – Purple `#8b5cf6`
5. **ML** (Introduction to Machine Learning) – Rose `#f43f5e`
6. **Maths** (Discrete Mathematics) – Amber `#f59e0b`

## Advanced Features & AI Integration

### 1. Smart / Deep Mode AI Assistant
Revision Hub features a fully integrated AI study assistant with two modes:
- **Smart Mode (WebGPU):** Uses a local LLM running directly in the browser via WebGPU (e.g., Llama/Qwen) for zero-latency, private, offline inferences.
- **Deep Mode (Cloud):** Uses Groq's high-speed API (qwen2.5-32b, llama-2-7b, etc.) for complex reasoning and deep syllabus analysis. Deep mode is the default.
The assistant is context-aware of the current subject and intelligently parses the assistant-index.json RAG database to ground its answers in the exact syllabus material.

### 2. Markdown-Powered Cheat Sheets
Cheat sheets have been upgraded from simple static cards to dense, heavily-structured, single-column Markdown documents. 
- Generated by AI agents from the questions.json data and dbms_cheatsheet.md templates.
- Features high-yield revision artifacts (incorporating 'Exam Traps', 'Pro-Tips', and tables) safely injected into the Glassmorphic UI cards.

### 3. Dynamic OBE Predictive Bias Matrix ("Important Only" Filter)
The Important Only filter is powered by a rigorously identified **Outcome-Based Education (OBE) Predictive Bias Matrix**. By analyzing historical midterm exams across subjects, the system flags high-yield questions based on the exact correlation between marks and Bloom's Taxonomy Cognitive Levels (KL):
- **Short Questions (2m):** Restricted to K1/L1 (Remember) and K2/L2 (Understand).
- **Medium Questions (3m):** Scaled to K2/L2 (Understand) and K3/L3 (Apply).
- **Long Questions (5m):** Strictly targets K3/L3 (Apply) and K4/L4 (Analyze) involving coding, designs, or complex queries.
This generalized prediction is systematically applied to the `questions.json` data via the `scripts/predictive_picker.py` automated pipeline.

### 4. Mobile-Optimized Workspace
The UI features a bottom-left stacked Floating Action Button (FAB) layout on mobile, intelligently sliding the AI Assistant over the syllabus without forcing keyboard popups, keeping the reading view completely unobstructed.

## The Generation Pipeline (`build_site.py`)
All HTML files inside subject folders are **statically generated**. Do not edit them by hand — they are overwritten on every `python build_site.py` run.

1. **Sources of Truth**:
   - `subjects/<subject>/<subject>_questions.json` (Long-form essays with `answer_html`. All `unit` properties are strictly validated and normalized to `I`, `II`, `III`, `IV`, `V` during build. Any other value fails the build.)
   - `subjects/<subject>/<subject>_quiz.json` (30 MCQ/Code/Short Answer questions per subject, generated by `scripts/generate_quizzes.py` using `GROQ_API_KEY` environment variable)
2. **Templates**:
   - `question-bank-template.html` — receives `questions`, `is_midterm`, `subject_code` from the build script
   - `quiz-template.html` — receives `quiz_data` from the build script
3. **Midterm filter**: Questions in Units I–III with `"important": true`


> **Architecture Note (v2.1):** All inline CSS `<style>` blocks (skeleton animations, quiz layouts) and inline `<script>` blocks have been strictly segregated into `shared/design-system.css` and `shared/quiz-logic.js` to ensure clean separation of concerns.

> **After editing any template or JSON, always run `python build_site.py` to regenerate all HTML files.**

## Premium Design System

### 1. The "Black Glass" Aesthetic
- **Background**: `#030303`. Every page includes `<div class="glow-bg"></div>` to cast blurred ambient mesh color radial-gradients.
- **Glassmorphism**: `background: rgba(20,20,20,0.5)` + `backdrop-filter: blur(16px)` + `border: 1px solid rgba(255,255,255,0.06)`.
- **Critical Chromium Bug**: Never add `contain: paint` or `will-change: opacity/transform` to a parent that has a child with `backdrop-filter`. This breaks the blur entirely — the element becomes transparent.
- **No Drop Shadows**: Depth is achieved through atmosphere and blurs only.
- **Global Color Synchronization**: All atmospheric elements (`.glow-bg`), floating action buttons (`.fab-main`), and progress bars dynamically map to the active subject's `--subject-color-rgb`, ensuring a flawlessly unified color palette across internal pages.

### 2. Typography (Google Fonts)
- **`Inter`**: UI Chrome — badges, topbars, body text, modals.
- **`Outfit`**: Headings & Brand — `<h1>`, trophies, brand names.
- **`JetBrains Mono`**: Code blocks and quiz code questions.
- Page `<h1>` uses a `linear-gradient` from `--subject-color` into `--heading-color`, clipped to text.

## Performance & Rendering Architecture

### Page Transitions & GPU Acceleration
- **Native Cross-Document Fading**: `<meta name="view-transition" content="same-origin">` is active on all pages, enabling seamless, native cross-document morphing.
- **Composite-Layer Isolation (`will-change`)**: The massive hero text with `-webkit-background-clip: text` and the infinite floating trophy icon are explicitly promoted to their own GPU layers using `will-change: opacity, transform`. This totally eliminates main-thread rasterization lag during the page load sweep.
- **Performant Ambient Backgrounds**: Expensive full-viewport `filter: saturate()` animations were completely removed from the `.glow-bg` radial gradients. They are replaced by highly-performant `transform: scale()` composite sweeps to prevent heavy main-thread filter calculations.

### CSS First-Paint Optimizations
- **Body Background Hardcoding**: Every template's `<body>` tag has an inline `style="background:#030303;"`. This ensures a pitch-black first frame while the CSS stylesheet is parsing.
- **Synchronized Skeleton Loaders**: The question bank templates and static cheat sheets utilize a pure CSS skeleton screen that exactly mimics their internal layout structures (e.g. 8 slim accordions for banks, 3-column grid for cheat sheets). The skeleton naturally drops from the render tree via an animation after `350ms`. 

### IntersectionObserver & Staggered Batches
- **Row-Batched Dashboard Entrance**: The Dashboard subject cards use an `IntersectionObserver` paired with `requestAnimationFrame`. The animation math calculates delay via row (`Math.floor(index / 3) * 0.15s`) instead of a column wave, forcing entire rows of 3 subjects to pop up synchronously from a deep `translateY(60px)` offset.
- **Scroll-Aware Content Reveal**: The huge `150+` question bank arrays are lazy-animated. To prevent lag on massive lists, `app-utils.js` dynamically checks `getBoundingClientRect().top` on page load. It only injects heavy staggered transition delays onto `.q-card` elements that are *actually visible above the fold*. The offset (`0.2s`) is mathematically synced to trigger the exact millisecond the wrapper's skeleton finishes fading out.

### Scroll Restoration & Frame Drop Fixes
- **Forced Homepage Anchoring**: Native browser scroll restoration is explicitly disabled for the dashboard (`history.scrollRestoration = 'manual'`) and paired with `window.scrollTo(0, 0)`.
- **Two-Tier JS Execution (`shared/app-utils.js`)**: 
  - *Eager (Critical)*: Theme apply, manual scroll restore, basic listeners.
  - *Deferred (Non-Critical)*: Review state, filter wiring, and observer registration are scheduled via `requestIdleCallback` after `280ms` to run silently in the browser's free time after the CSS entry animation ends.

## Mobile UX & Layout Stability


- **Responsive Card Density**: Code block cards (`.quiz-container`, `.q-card`) strictly enforce an `800px` max-width constraint on Desktop monitors for optimal eye-tracking. On mobile breakpoints (`max-width: 768px`), this expands to a fluid `100%` width with `min-width: 0` to override flex algorithms and prevent long, unbreakable Java lines from stretching the viewport horizontally.
- **Tap Highlight Eradication**: Global `-webkit-tap-highlight-color: transparent` prevents jarring translucent blue overlay boxes when interacting with cards on iOS/Android touch devices.

## Core Features & Mechanics

### Print & PDF Generation
- **Client-Side Export**: Added a "Save as PDF" button natively hooked into `window.print()`.
- **Dynamic Pre-rendering**: Intercepts the click to automatically strip all animations and force-open every `details.q-card` accordion so no hidden answers are truncated in the final PDF.
- **Dedicated Print Stylesheet (`@media print`)**: Automatically forces a high-contrast white background, wraps long code blocks, injects a custom watermark (`made by nihal`), disables the sticky progress bar, and strips out `navbar`/`FAB` UI elements to produce a clean, ink-friendly document.

### Dashboard (Landing Page)
- Premium 100vh Hero section with "The Mission" and "The Algorithm" panels.
- **IntersectionObserver Animations**: Subject cards stagger and float up as the user scrolls.
- **Trophy System**:
  - 🥈 **Midterm Ready**: Unlocks *only* when the exact set of Midterm question IDs (baked into `index.html` at build time) are verified as `true` in `localStorage`.
  - 🏆 **Mastered**: Unlocks when 100% of the question bank is reviewed.

### Interactive "Quick FAQ"
- Picks 10 random questions from a pool of 30 per subject on every page load.
- Supports 3 question types: **MCQ** (clickable options), **Code** (type-to-verify), **Short Answer** (one-word verify with manual override).
- "Reveal Answer" button skips and shows the full explanation.
- "I was actually right" override button forgives strict string matching.

### Flashcards
- Launched from the FAB menu on any question bank page.
- Reads the live filtered DOM — only shows questions currently visible after any applied filters.
- Deck is Fisher-Yates shuffled on every launch.

### Ghost Data Scrubbing
- On every `loadReviewState()` call, empty string `""` and `"null"` keys are deleted from `localStorage` before counting reviewed questions. This prevents phantom progress inflation.

## Navigation Architecture

### Smart Topbar
Fixed, frosted-glass navbar. Hides on scroll-down, reappears on scroll-up (headroom pattern). Subject code (e.g. `ML`, `DBMS`) is baked directly into the HTML by `build_site.py` via the `{{ subject_code }}` Jinja variable — no JS path-parsing needed.

### Floating Action Button (5-item Vertical Stack)
Fixed, bottom-right. Right-aligned vertical stack:
1. **Flashcards** — launches study mode
2. **Mark All** — marks/unmarks all visible questions
3. **Jump** — opens `#jumpModal`
4. **Filter** — opens `#filterModal`
5. **Top** — smooth scroll to top

### Glass Modals
- **`#jumpModal`**: Unit quick-jump links (Jinja-generated per unit).
- **`#filterModal`**: Live search input + unit/marks/bloom/important/reviewed checkboxes. Includes a globally scoped `window.clearFilters()` function that robustly wipes DOM-synced search text (`#search-box`), resets all checkboxes, and instantly re-triggers the UI.
- **`#studyModal`**: Full-screen Flashcard app.
- **`#congratsModal`**: Dynamically injected on 100% completion.

## How to Run & Develop Locally

### Prerequisites
- **Python 3.x** (Required for the build script and Jinja2)
- **Jinja2** (`pip install jinja2`)

### Workflow
1. **Edit Source Data**: Add or modify questions by editing the JSON files located inside the `data/<subject>/` directory (e.g., `data/dbms/dbms_questions.json`).
2. **Edit Master Templates**: To change the HTML layout for the question banks, edit the files inside the `/templates/` directory. (Do NOT edit the generated HTML files inside the `subjects/` folders directly).
3. **Build the Site**: Open a terminal in the root `revision-hub` directory and run the build script to regenerate all HTML pages:
   ```bash
   python scripts/build_site.py
   ```
4. **Test Locally**: Run a simple Python web server to view the site:
   ```bash
   python -m http.server 8000
   ```
   Then open `http://localhost:8000` in your browser.

## Deployment
Hosted on **Vercel**: `https://larping-study.vercel.app`

Drag-and-drop the `revision-hub` folder to the Vercel dashboard to trigger a production update. `revision-hub.zip` on the Desktop is always kept in sync after each session.

### Vercel Serverless API (Deep Mode)
The project utilizes Vercel Serverless Functions (`api/chat.js`) to securely communicate with the Groq API without exposing the API key on the client side. 
**Required Vercel Environment Variables:**
- `GROQ_API_KEY`: Your Groq API Key (Set Type to **Secret**).
- `GROQ_MODEL`: The specific model to use, e.g., `llama-3.1-70b-versatile` (Set Type to **Config**).
- `ALLOWED_ORIGINS`: Your production URL, e.g., `https://larping-study.vercel.app` (Set Type to **Config**).

*Note: Vercel "Secret" variables are write-only. If you need to edit a Secret, it is highly recommended to delete it and recreate it to avoid Vercel UI bugs.*

### Ask AI Assistant
- **Global Brain Indexing**: `scripts/build_site.py` aggregates all subject chunks into a massive `subjects/global/assistant-index.json`, allowing cross-subject querying directly from the homepage.
- **Dynamic Smart Mode (WebGPU)**: Runs **Meta Llama 3.2** natively in the browser via `@mlc-ai/web-llm`. It intelligently checks `navigator.gpu` and VRAM, dynamically downloading either the 3B model (for laptops) or the 1B model (for low-memory devices).
- **Graceful Mobile Fallback (Lite Mode)**: If WebGPU is unavailable (mobile devices or older browsers), the assistant instantly defaults to "Lite Mode"—a highly-optimized, offline JavaScript search engine utilizing BM25 and fuzzy keyword matching that runs at 60fps on any CPU.
- **Deep Mode (Cloud AI) & Exponential Backoff**: Uses the Vercel Serverless backend to query Groq. If the Groq API is overloaded and returns a `503 Service Unavailable`, the client automatically implements an exponential backoff retry mechanism (1s, 2s, 4s) to seamlessly power through temporary demand spikes without dropping the user into Lite Mode.
- **Deep Routing**: The UI securely parses deep links generated by the AI (`onclick="return !appUtilsOpenCard('q51');"`), navigating seamlessly between global domains or smoothly scrolling to questions if they exist on the current page.
- **UI Integration**: A standalone `Ask AI` FAB is permanently anchored to the bottom-left (`bottom: 2rem; left: 2rem;`) of the Dashboard, Question Banks, Interactive Quizzes, and Cheat Sheets.
