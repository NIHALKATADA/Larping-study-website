Unit I: Introduction & Basics CO1

OS Basics & Functions

  • Process Mgmt: Scheduling, creation, termination.
  • Memory Mgmt: RAM allocation/deallocation.
  • File Mgmt: Organizing files and directories.
  • Device Mgmt: I/O management & drivers.

Process Schedulers

  • Long-Term (Job): Disk → Ready Queue. Controls multiprogramming.
  • Short-Term (CPU): Ready Queue → CPU. Fast.
  • Medium-Term: Swaps processes (RAM ↔ Disk).

Deadlock Handling

  • Prevention: Negate 1 of 4 conditions.
  • Avoidance: Banker's Algorithm (Safe states).
  • Detection & Recovery: Wait-for graphs, killing processes.
  • Ignorance: Ostrich Algorithm (Unix/Windows).

Unit II: Core Mechanics CO2

Dual-Mode Operation

ModeBitAccess
Kernel0Full hardware & instructions
User1Restricted access

Timer Interrupts prevent user programs from hogging CPU.

Scheduling Metrics

  • Arrival Time (AT): When process enters Ready.
  • Burst Time (BT): CPU time needed.
  • Completion Time (CT): When process finishes.
  • TAT: CT - AT
  • WT: TAT - BT

Memory Management

  • Paging: Fixed-size blocks (Pages/Frames). No external fragmentation.
  • Segmentation: Variable-size logical segments (Code, Data). External fragmentation possible.
  • TLB: Hardware cache for Page Table entries.

Unit III: Advanced Concepts CO3

OS Architectures

  • Monolithic: High performance, hard to maintain (e.g., Early Linux).
  • Microkernel: Highly stable/secure, slow due to IPC (e.g., Mach).
  • Module-Based (Hybrid): Best of both; dynamic modules (Modern Linux).

Virtual Memory & Thrashing

Virtual Memory: Allows execution of processes not completely in RAM. Uses Swap space on disk.

Thrashing: System spends more time paging than executing due to high page fault rate.

Unit V: Modern Ecosystem CO5

PCB & Context Switch

PCB Stores: State, PID, PC, Registers, Memory Limits.

Context Switch: Saving state of old process into its PCB & loading state of new process from its PCB.

Deadlock Conditions (Coffman)

  1. Mutual Exclusion: ≥1 resource is non-shareable.
  2. Hold and Wait: Holding a resource while waiting for another.
  3. No Preemption: Resources can't be taken forcibly.
  4. Circular Wait: A → B → C → A.

Disk Scheduling

  • FCFS: Simple, poor performance.
  • SSTF: Shortest Seek Time First. Starvation possible.
  • SCAN: Elevator algo (goes to one end, reverses).
  • C-SCAN: Circular SCAN (returns to start without servicing on way back).
