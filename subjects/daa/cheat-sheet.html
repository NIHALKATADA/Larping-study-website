Unit I: Introduction & Foundations CO1

Algorithm Fundamentals

A rigorous sequence of unambiguous computational steps transforming input to output. Crucial properties include definiteness (unambiguous steps) and effectiveness (basic feasible operations).

Example: Euclid's algorithm for GCD(a,b) where a=12, b=8 yields 4 via systematic reduction.

Loop Invariants (Correctness Proofs)

Formal logical assertions that remain true before, during, and after loop execution, utilized inductively to prove algorithmic correctness.

Example: In Insertion Sort, `A[1...i-1]` is always sorted before the i-th iteration commences.

Pro Tip: Examiners test initialization, maintenance, and termination. Ensure the termination property directly implies the overall postcondition.

Asymptotic Notations

Mathematical abstractions characterizing growth rates: O(n) (asymptotic upper bound, worst-case), Ω(n) (lower bound, best-case), and Θ(n) (tight bound, average-case).

Example: Mergesort is strictly Θ(n log n) as best and worst-case trees have identical depth.

Recurrence Solving (Substitution)

A deductive technique establishing asymptotic complexity by positing a bound and applying mathematical induction to verify it against the recurrence relation.

Example: T(n) = 2T(n/2) + n. Guess O(n log n), prove T(n) ≤ c(n log n) inductively.

Exam Trap: When using Substitution, you must explicitly prove the exact form of your guess. Do not ignore lower-order terms during the inductive step!

Unit II: Core Algorithmic Paradigms CO2

Divide and Conquer Methodology

A paradigm that recursively partitions a problem into disjoint subproblems, solves them, and amalgamates their solutions. Relies heavily on recurrence relations.

Example: Strassen's Matrix Multiplication reduces subproblems from 8 to 7, dropping complexity to O(n^2.81).

Master Theorem Deep-Dive

A deterministic method for solving recurrences of the form T(n) = aT(n/b) + f(n). Compares f(n) against n^(log_b(a)) using polynomial boundedness.

Example: T(n) = 9T(n/3) + n. a=9, b=3, log_3(9)=2. n^2 > n, hence Case 1: T(n) = Θ(n^2).

Exam Trap: The Master Theorem ONLY applies if the difference between f(n) and n^(log_b(a)) is polynomially large. It fails for T(n) = 2T(n/2) + n log n!

Greedy Paradigm & Matroids

An optimization strategy making locally optimal choices with the heuristic that it converges to a global optimum. Only valid if the problem exhibits the greedy-choice property and optimal substructure.

Example: Huffman Coding optimally minimizes prefix-free code length by greedily merging lowest frequency nodes.

Paradigm Decision Tree

flowchart TD A[Optimization Problem] --> B{Overlapping Subproblems?} B -- Yes --> C(Dynamic Programming) B -- No --> D{Optimal Substructure?} D -- Yes & Greedy Choice --> E(Greedy Algorithm) D -- Yes & Disjoint --> F(Divide & Conquer)

Example: Use this mental model to quickly classify DP (Fibonacci) vs Divide & Conquer (Merge Sort).

Unit III: Dynamic Programming & Complexity CO3

Dynamic Programming (DP)

Systematically exhausts all possibilities by caching solutions to overlapping subproblems (memoization/tabulation), guaranteeing a global optimum for complex state spaces.

Example: Matrix Chain Multiplication optimally parenthesizes a chain of matrices in O(n^3) using a cost table.

Bellman-Ford vs Dijkstra

graph LR A((S)) -- 5 --> B((U)) A -- 4 --> C((V)) B -- -6 --> C

Dijkstra uses a priority queue (Greedy) but fails catastrophically with negative weights. Bellman-Ford repeatedly relaxes all edges (DP) and detects negative cycles on the V-th pass.

Example: Routing in networks where path costs can become negative due to subsidies requires Bellman-Ford.

0/1 vs Fractional Knapsack

Fractional allows splitting items (solvable greedily by sorting value/weight ratio). 0/1 strictly forbids splitting, invalidating the greedy choice and mandating DP.

Example: Packing discrete gold bars (0/1 DP) vs packing gold dust (Fractional Greedy).

Exam Trap: Applying greedy value/weight ratio to 0/1 Knapsack is the most common student error. Always use the DP table: `dp[i][w] = max(dp[i-1][w], val[i] + dp[i-1][w-wt[i]])`.

Unit IV: Advanced Graph Algorithms CO4

Minimum Spanning Trees (MST)

Acutely optimizes network connectivity. Kruskal's sorts edges globally (uses Disjoint-Set/Union-Find). Prim's grows a single tree locally from a root (uses Min-Heap).

Example: Kruskal's O(E log E) is ideal for sparse graphs; Prim's O(E + V log V) with Fibonacci heaps dominates dense graphs.

Network Flow (Ford-Fulkerson)

Calculates the maximum flow in a flow network. It iteratively finds augmenting paths in a residual graph until none exist. Relies heavily on the Max-Flow Min-Cut theorem.

Example: Maximizing water flow through a plumbing network with distinct pipe capacities.

Pro Tip: The Edmonds-Karp implementation uses BFS to find augmenting paths, strictly bounding execution time to O(V E^2) unlike naive DFS.

All-Pairs Shortest Path (Floyd-Warshall)

A quintessential DP algorithm computing shortest paths between all vertex pairs in O(V^3) time. It incrementally allows intermediate vertices from {1...k}.

Example: Generating a complete distance matrix for a GPS routing system between all major cities.

Unit V: NP-Completeness & Approximation CO5

P vs NP Classes

P: Solvable in polynomial time. NP: Solutions are verifiable in polynomial time by a non-deterministic Turing machine.

Example: Sorting is in P. Sudoku solving is in NP (fast to check a solved board, hard to solve).

NP-Complete Reductions

A problem Y is NP-Complete if it's in NP and every NP problem polynomial-time reduces to Y. To prove a new problem Y is NPC, reduce a known NPC problem X to Y.

Example: Reducing 3-SAT (known NPC) to Clique (target Y) to prove Clique is NP-Complete.

Exam Trap: Reduction direction matters! To prove Y is hard, reduce the KNOWN hard problem X to Y (X -> Y). Reducing Y to X proves nothing about Y's difficulty.

Approximation Algorithms

Heuristics for NP-Hard problems that guarantee a solution within a specific multiplicative factor (ρ) of the absolute optimal cost in polynomial time.

Example: The 2-Approximation for Vertex Cover using a greedy maximal matching guarantees the cover is at most twice the optimal size.

Complexity Hierarchy

flowchart BT P((P)) --> NP((NP)) NPC((NP-Complete)) --> NP NPC -.-> NPH((NP-Hard)) NP -.-> NPH

Example: Halting Problem is NP-Hard but not NP-Complete (since it's undecidable and thus not in NP).
