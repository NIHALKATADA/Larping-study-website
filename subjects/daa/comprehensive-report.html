Unit I: Algorithm Fundamentals & Analysis

Algorithm Definition & Pseudocode

Algorithm: A finite, unambiguous sequence of instructions to solve a specific problem.

Four Characteristics of a Good Algorithm:

  • Finiteness: Must terminate after a finite number of steps.
  • Definiteness: Each step must be clear and unambiguous.
  • Input/Output: Zero or more inputs; at least one output.
  • Effectiveness: Basic enough to be carried out manually.
Exam Trap: Don't confuse finiteness (termination) with definiteness (clarity).

Pseudocode: High-level description of an algorithm that uses structural conventions of programming languages but is intended for human reading.

Advantages of Pseudocode:

  • Language-independent, making it easier for any programmer to understand.
  • Easier to write, debug, and modify compared to actual code.
With Algorithm Definition & Pseudocode in mind, we can see why Complexity & Asymptotic Analysis becomes crucial in this context.

Complexity & Asymptotic Analysis

Time Complexity vs. Space Complexity:

  • Time Complexity: The amount of time an algorithm takes to run as a function of the input length.
  • Space Complexity: The amount of memory an algorithm needs to run as a function of the input length.
Example: An algorithm creating an array of size n requires O(n) space complexity, while iterating through it takes O(n) time complexity.

Asymptotic Analysis: Evaluating performance as input size grows to infinity.

Pro-Tip: It's preferred over measuring execution time because it ignores hardware differences, focusing strictly on algorithm efficiency.

Analysis Cases:

  • Best-case: Minimum time needed (often occurs when data is already perfectly arranged).
  • Worst-case: Maximum time needed (most crucial for guaranteeing performance).
  • Average-case: Expected time over all possible inputs.

Big-O Notation: Represents the upper bound (worst-case scenario) of time complexity. It describes the maximum growth rate.

Amortized Analysis (Aggregate Method): Averages time over a sequence of operations to guarantee the average performance of each operation. The aggregate method simply calculates the total cost of a sequence of n operations and divides by n.

While Complexity & Asymptotic Analysis gives us the theoretical background, Calculating Time Complexity Examples provides the next layer of complexity.

Calculating Time Complexity Examples

1. Basic Assignment:

sum = 0; a = 5; b = 10; sum = a + b; printf("%d", sum);

Complexity: O(1) (Constant number of simple statements).

2. Conditional Statements:

if (n > 100) x = x + 1; else x = x - 1;

Complexity: O(1). Both best and worst cases are O(1) since both branches involve basic operations.

3. Simple For Loop:

for(i = 1; i <= n; i++) { printf("%d", i); }

Complexity: O(n) (Loop runs n times).

4. Step For Loop:

for(i = 1; i <= n; i = i + 2) { count++; }

Complexity: O(n) (Loop runs n/2 times, which simplifies to O(n)).

5. Nested For Loop (Square):

for(i = 1; i <= n; i++) { for(j = 1; j <= n; j++) { count++; } }

Complexity: O(n²) (Inner loop runs n times for each of the n iterations of the outer loop).

6. Nested For Loop (Triangle):

for(i = 1; i <= n; i++) { for(j = 1; j <= i; j++) { count++; } }

Complexity: O(n²) (Total operations = 1 + 2 + ... + n = n(n+1)/2 = O(n²)).

7. Multiplicative For Loop:

for(i = 1; i <= n; i = i * 2) { printf("%d", i); }

Complexity: O(log n) (i doubles each time, taking log₂(n) steps to reach n).

Unit II: Algorithm Correctness & Sorting

Algorithm Correctness & Loop Invariants

Algorithm Correctness: An algorithm is correct if, for every valid input, it halts and produces the correct output.

  • Partial Correctness: IF the algorithm halts, it produces the correct output.
  • Total Correctness: It is partially correct AND it is guaranteed to halt.
Example: A while(true) loop computing correct intermediate states is partially correct, but not totally correct because it never halts.

Loop Invariant: A condition that is true before and after each iteration of a loop.

Three Steps to Prove Correctness:

  1. Initialization: It is true prior to the first iteration.
  2. Maintenance: If it is true before an iteration, it remains true before the next iteration.
  3. Termination: When the loop terminates, the invariant gives a useful property that helps show the algorithm is correct.

Sorting Correctness: In sorting (e.g., Insertion Sort), a loop invariant could be: "The subarray A[1..i-1] consists of the original elements but in sorted order." Showing it holds until the end proves the entire array is sorted.

With Algorithm Correctness & Loop Invariants in mind, we can see why Comparison Sorting & Dry Runs becomes crucial in this context.

Comparison Sorting & Dry Runs

Bubble Sort: Repeatedly swaps adjacent elements if they are in the wrong order. O(n²).

Dry Run (Bubble Sort): Pass 1 swaps largest to end, Pass 2 next largest, etc. For [64, 25, 12, 22, 11, 90, 34, 5, 78, 43], after Pass 1: [25, 12, 22, 11, 64, 34, 5, 78, 43, 90]. (Also applied to: [90, 80, 70, 60, 50, 40, 30, 20, 10] which sorts perfectly in reverse).

Selection Sort: Repeatedly finds the minimum element from the unsorted part and puts it at the beginning. O(n²).

Dry Run (Selection Sort): [29, 10, 14, 37, 13, 25, 8, 42, 17] -> Pass 1: Min is 8. Swap 29 and 8. Array: [8, 10, 14, 37, 13, 25, 29, 42, 17]. Same logic applies to [64, 25, 12, 22, 11, 90, 34, 5, 78, 43].

Insertion Sort: Builds the final sorted array one item at a time by inserting elements into their correct position. O(n²) worst case.

Dry Run (Insertion Sort): [45, 12, 78, 34...] -> Pass 1: Insert 12 before 45 -> [12, 45, 78, ...]. Applied similarly for reverse sorted [9, 8, 7, 6, 5, 4, 3, 2, 1].
Comparison: All three are O(n²), but Insertion sort is best for nearly sorted data. Bubble is easiest to implement. Selection sort minimizes the number of swaps. Comparing on [64, 34, 25, 12, 22, 11, 90, 45, 78, 33] evaluates swap/comparison efficiency based on initial partially sorted subarrays.
With Comparison Sorting & Dry Runs in mind, we can see why Heaps & Heap Sort becomes crucial in this context.

Heaps & Heap Sort

Heap Definition: A complete binary tree satisfying the heap property.

  • Max Heap: The key of a node is ≥ the keys of its children.
  • Min Heap: The key of a node is ≤ the keys of its children.
Is Array a Max Heap? [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]. Yes, check index i vs 2i and 2i+1. e.g., 16 ≥ 14 and 10.

BUILD-MAX-HEAP vs. MAX-HEAPIFY:

  • MAX-HEAPIFY: Maintains the max-heap property assuming child subtrees are already max heaps. Time: O(log n).
  • BUILD-MAX-HEAP: Runs MAX-HEAPIFY on all non-leaf nodes bottom-up to create a max heap from an unordered array. Time: O(n).
Bottom-up Heap Construction: [45, 20, 14, 12, 31, 7, 11, 13, 8, 10]. Leaves are [7, 11, 13, 8, 10]. Heapify nodes backwards from index n/2 down to 1.
Heap Sort Dry Runs: (On [25, 17, 36, 2, 3, 100, 1, 19, 7] and [20, 15, 30, 5, 10, 25, 35, 2, 8, 12]). Build max heap. Swap root with last element, reduce heap size, MAX-HEAPIFY root. Repeat until size is 1.
Now that we have a solid grasp of Heaps & Heap Sort, the natural next step is to explore Non-Comparison Sorting & Dry Runs.

Non-Comparison Sorting & Dry Runs

Counting Sort: Counts occurrences of each object. Good for small range integers. Time: O(n + k).

Dry Run (Counting Sort): [4, 2, 7, 3, 2, 1, 6, 4, 3, 5] & [3, 1, 4, 1, 2, 7, 5, 3, 6, 2]. Count array counts occurrences. Prefix sums determine positions in output array.

Radix Sort: Sorts digit by digit starting from least significant digit using a stable sort (like Counting Sort). Time: O(d(n + k)).

Dry Run (Radix Sort): [170, 45, 75, 90, 802, 24, 2, 66, 329, 501] & [329, 457, 657, 839, 436, 720, 355, 12, 98]. Pass 1 (1s place), Pass 2 (10s place), Pass 3 (100s).

Bucket Sort: Divides elements into buckets, sorts each bucket individually (e.g., with Insertion Sort), and concatenates. Time: O(n) average.

Dry Run (Bucket Sort): [0.42, 0.32, 0.73, 0.52, 0.25, 0.91, 0.63, 0.18, 0.37, 0.81]. Create 10 buckets (0.0-0.1, 0.1-0.2, etc.). Distribute, sort internally, concatenate.
Complexities Summary: Bubble/Selection/Insertion = O(n²). Heap = O(n log n). Counting/Bucket/Radix = O(n) (under specific conditions).

Unit III: Divide and Conquer

Divide and Conquer Paradigm

Divide and Conquer Paradigm: A recursive approach to solving problems.

Three Basic Steps:

  1. Divide: Break the problem into smaller subproblems.
  2. Conquer: Solve the subproblems recursively (or directly if small enough).
  3. Combine: Merge the solutions to form the overall answer.

Comparison to Iterative: Iterative uses loops (bottom-up), while Divide and Conquer uses recursion (top-down dividing). D&C is powerful for parallel processing and complex problems, but recursion adds overhead (stack memory).

Advantages & Limitations: Adv: Solves complex problems elegantly, natural parallelism. Lim: Recursive overhead, potentially slower for small datasets.

Do these algorithms use D&C?

  • Binary Search: Yes. Divides array in half, conquers one half, combining is trivial.
  • Merge Sort: Yes. Divides array in half, sorts halves, combines via merge.
  • Quick Sort: Yes. Divides via partition, sorts partitions.
  • Bubble Sort: No. Iterative approach, swaps adjacent elements.
Moving forward from Divide and Conquer Paradigm, let's break down the mechanics of Solving Recurrences.

Solving Recurrences

Recurrence Relation: An equation that expresses T(n) in terms of T(n/b) or T(n-1). Used to analyze recursive algorithm time complexity.

Substitution Method:

  • T(n) = 2T(n/2) + n: Guess O(n log n). Prove by induction.
  • T(n) = T(n/2) + 1: Expand to T(n/4) + 1 + 1... eventually T(1) + log n = O(log n).

Master Method (T(n) = aT(n/b) + f(n)):

  • T(n) = 2T(n/2) + n: a=2, b=2, f(n)=n. log₂(2) = 1. Case 2: O(n log n).
  • T(n) = 4T(n/2) + n: a=4, b=2, f(n)=n. log₂(4) = 2 > 1. Case 1: O(n²).
  • T(n) = 4T(n/2) + n²: a=4, b=2, f(n)=n². log₂(4) = 2. Case 2: O(n² log n).
  • T(n) = 8T(n/2) + n²: a=8, b=2, f(n)=n². log₂(8) = 3 > 2. Case 1: O(n³).
  • T(n) = T(n/2) + 1: a=1, b=2, f(n)=1. log₂(1) = 0. Case 2: O(log n).
Now that we have a solid grasp of Solving Recurrences, the natural next step is to explore Searching Algorithms & Max-Min.

Searching Algorithms & Max-Min

Binary Search vs Linear Search:

  • Linear Search: Best O(1), Avg O(n), Worst O(n).
  • Binary Search: Best O(1), Avg O(log n), Worst O(log n). Requires array to be sorted.
Warning: If Binary Search is applied to an unsorted array, it may eliminate the half containing the target element, leading to false negatives.
Binary Search Dry Run (Success): [5, 12, 18, 23, 31, 37, 45, 52, 64, 71, 85]. Search for 45. Mid=37, 45>37 so search right half. Mid=64, 45<64 so search left. Mid=45. Found!
Unsuccessful Dry Run: Search 50 in [3, 8, 12, 17, 21, 29, 34, 41, 56, 63, 72, 89]. Continues until low > high termination occurs without finding 50.

Max-Min via Divide & Conquer: Divides array into two halves, recursively finds (max, min) of each half, and combines by taking max of maxes and min of mins. Reduces number of comparisons to 3n/2 - 2.

Max-Min Dry Run: [35, 12, 48, 7, 23, 56, 19, 4, 31, 15] -> Divide until sizes 1 or 2. E.g., (35,12) -> max=35, min=12. Combine tree upwards.
To fully appreciate D&C Sorting & Advanced Multiplication, we must apply what we just learned about Searching Algorithms & Max-Min.

D&C Sorting & Advanced Multiplication

Merge Sort Dry Run: [38, 27, 43, 3, 9, 82, 10, 15, 21, 6]. Split to singletons, merge iteratively maintaining order. e.g., merge [27, 38] and [3, 43].
Quick Sort Dry Run: [64, 25, 12, 22, 11, 90, 34, 5, 78, 43]. Pivot=64. Partition so left < 64, right > 64. Recursively sort partitions.

Quick Sort Complexity: Best/Avg: O(n log n). Worst: O(n²) (when already sorted and choosing first element as pivot).

Merge Sort vs Quick Sort:

  • Stability: Merge sort is stable (preserves order of equals). Quick sort is typically unstable.
  • When to use: Merge sort for linked lists or guaranteed O(n log n) needs. Quick sort for general in-memory arrays (faster in practice, O(1) space).

Strassen's Matrix Multiplication: Traditional matrix multiplication requires 8 multiplications for 2x2 blocks (O(n³)). Strassen uses 7 multiplications, reducing complexity to O(n^2.81).

Large Integer Multiplication (Karatsuba): Standard multiplication is O(n²). D&C divides n-digit numbers into halves, requiring 3 recursive multiplications instead of 4, reducing time to O(n^1.58).
