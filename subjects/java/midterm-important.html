Q3. Define Object-Oriented Programming and list the six pillars of OOP.

Unit II CO2 | Bloom L2 2 Marks Score: 9.5

Object-Oriented Programming (OOP) is a paradigm centered around "objects" (which contain data in the form of fields and code in the form of methods) rather than "actions" or logic.

The six pillars (or core concepts) of OOP are:

  1. Class
  2. Object
  3. Encapsulation
  4. Abstraction
  5. Inheritance
  6. Polymorphism

Q5. Define encapsulation, abstraction, inheritance, and polymorphism.

Unit II CO2 | Bloom L2 2 Marks Score: 10.0
  • Encapsulation: Wrapping data (variables) and code (methods) together into a single unit (class), protecting the data from outside interference.
  • Abstraction: Hiding internal implementation details and exposing only the necessary functionalities to the user.
  • Inheritance: A mechanism where a new class (child) inherits properties and behaviors from an existing class (parent), promoting code reusability.
  • Polymorphism: The ability of a single entity (method, object, or operator) to take on multiple forms and behave differently based on the context.

Q7. What are JDK, JRE, and JVM?

Unit I CO1 | Bloom L2 2 Marks Score: 9.5
  • JDK (Java Development Kit): A full software development environment. It contains the JRE plus development tools like the compiler (javac) and debugger.
  • JRE (Java Runtime Environment): The environment required to run Java programs. It contains the JVM and core class libraries.
  • JVM (Java Virtual Machine): An abstract machine that executes Java Bytecode. It makes Java platform-independent.

Q8. What is bytecode, and why is Java considered platform-independent?

Unit I CO1 | Bloom L2 2 Marks Score: 9.5

Bytecode is a highly optimized set of instructions generated by the Java compiler (javac) after compiling the source code. It is not machine code, but rather intermediate code.

Java is platform-independent because the compiler generates this bytecode instead of native machine code. This bytecode can be executed on any operating system as long as that system has a JVM (Java Virtual Machine) installed to interpret it (Write Once, Run Anywhere).

Q10. List the four access modifiers in Java and state the default access level.

Unit II CO2 | Bloom L1 2 Marks Score: 9.0

The four access modifiers in Java (from most restrictive to least) are:

  1. private (accessible only within the same class)
  2. default (no keyword; accessible only within the same package)
  3. protected (accessible within the same package and subclasses in other packages)
  4. public (accessible from anywhere)

If no modifier is specified, the access level is default (package-private).

Q41. Explain the difference between stack and heap memory in Java with respect to object creation and references.

Unit II CO2 | Bloom L2 3 Marks Score: 9.5
  • Heap Memory: This is where all actual objects and instance variables are stored. It is dynamically allocated at runtime when the new keyword is used. It is managed by the Garbage Collector.
  • Stack Memory: This is where all local variables, method calls, and object references are stored. When you write Car c = new Car();, the object itself goes in the heap, but the reference variable c is kept in the stack, pointing to the heap memory address.

Q55. Differentiate between compile-time and run-time polymorphism in Java.

Unit III CO3 | Bloom L2 3 Marks Score: 9.0

Q63. Explain Java's platform independence in detail, from source code compilation to bytecode execution through the JVM.

Unit I CO1 | Bloom L2 5 Marks Score: 9.5

Java's "Write Once, Run Anywhere" capability relies on its two-step execution process:

  1. Compilation: The developer writes Program.java (Source Code). The Java Compiler (javac) compiles this into Program.class. Instead of compiling it into machine-specific code (like C++), it compiles it into Bytecode. This bytecode is entirely independent of the underlying OS or hardware.
  2. Execution: The compiled bytecode is transported to any machine (Windows, Mac, Linux). That machine must have a JVM (Java Virtual Machine) installed. The JVM reads the bytecode and translates it into the specific machine-level instructions native to that exact operating system.

Therefore, while the JVM is platform-dependent, the Java program (bytecode) itself is totally platform-independent.

Q74. Explain constructor overloading and constructor chaining in Java. Compare their purpose, implementation, and execution using suitable examples involving this() and super().

Unit II CO2 | Bloom L3 5 Marks Score: 9.5

Overloading allows a class to have multiple constructors with different parameters. Chaining allows these constructors to call each other, or call the parent's constructor, to avoid duplicating initialization logic.

class Parent {
    Parent() { System.out.println("Parent init"); }
}
class Child extends Parent {
    int x, y;
    
    Child() {
        this(0, 0); // Constructor Chaining via this()
    }
    
    Child(int x, int y) { // Overloaded constructor
        super(); // Constructor Chaining via super() to Parent
        this.x = x;
        this.y = y;
    }
}

    double add(double a, double b) { return a + b; }
}

class Animal {
    void sound() { System.out.println("Generic sound"); }
}
class Dog extends Animal {
    // Overriding (Run-time Polymorphism)
    @Override
    void sound() { System.out.println("Bark"); }
}

Compile-time: The compiler binds the add() method based on the parameter data types provided. Run-time: The JVM binds the sound() method based on whether the actual heap object is an Animal or a Dog.

Q85. Explain dynamic binding in detail with a Java program using a superclass reference and subclass object. Also explain how method overriding is resolved at run time.

Unit III CO3 | Bloom L3 5 Marks Score: 9.5

Dynamic Binding occurs when the compiler cannot determine the method implementation at compile time, so the JVM resolves it during execution.

class Vehicle {
    void move() { System.out.println("Moving"); }
}
class Car extends Vehicle {
    @Override
    void move() { System.out.println("Driving on wheels"); }
}

public class Main {
    public static void main(String[] args) {
        Vehicle v = new Car(); // Superclass ref, Subclass object
        v.move(); // Outputs: Driving on wheels
    }
}

At compile time, the compiler ensures move() exists in Vehicle. At runtime, the JVM notices the object is actually a Car and executes the overridden version.

Q89. Explain generic programming in Java. Write examples of a generic class and a generic method, and state the advantages of type safety and code reusability.

Generics allow parameters for types, catching type errors at compile-time instead of runtime.

// Generic Class
class Box<T> {
