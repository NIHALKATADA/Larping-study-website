Unit I: Introduction to Java and Basic Programming Concepts

Programming Paradigms and Java's Evolution

Programming Paradigm: A style or way of programming (e.g., how structure and execution are organized).

  • Other Paradigms: Procedural (C), Functional (Haskell), Logic (Prolog).
  • Procedural vs. OOP: Procedural focuses on functions/steps; OOP focuses on data/objects. OOP offers better data security (encapsulation), reusability (inheritance), and approach (Bottom-Up vs Top-Down).
  • Top-Down vs. Bottom-Up: Top-Down breaks a main problem into sub-tasks (Procedural). Bottom-Up builds individual components/objects and combines them (OOP).
Java was officially announced by Sun Microsystems in 1995 and was originally named Oak.

Important Features of Java: Object-Oriented, Platform-Independent, Simple, Secure, Robust, Multithreaded.

Having established the core principles of Programming Paradigms and Java's Evolution, we now turn our attention to Java Architecture: JDK, JRE, JVM, and Platform Independence.

Java Architecture: JDK, JRE, JVM, and Platform Independence

Java's execution involves three main components:

  • JDK (Java Development Kit): Contains everything needed to develop and run Java (JRE + development tools like compiler javac).
  • JRE (Java Runtime Environment): Provides the libraries and JVM required to run Java applications (JVM + core libraries).
  • JVM (Java Virtual Machine): The engine that executes bytecode line by line.

Platform Independence: Java source code (.java) is compiled into bytecode (.class). This bytecode is platform-independent. The JVM translates bytecode into machine-specific code, making Java "Write Once, Run Anywhere" (WORA).

Bytecode is platform-independent, but the JVM is platform-dependent!
Transitioning from Java Architecture: JDK, JRE, JVM, and Platform Independence, we now examine Java Program Structure and Basics, which builds upon these foundational rules.

Java Program Structure and Basics

Basic Structure: A Java program consists of classes and methods. The entry point is the main method.

Example: Standard main signature: public static void main(String[] args)
  • Identifiers: Names given to classes, methods, variables. Must start with a letter, _, or $.
  • Conventions: Classes (PascalCase), methods/variables (camelCase), constants (UPPER_SNAKE_CASE).
  • Comments: Single-line (//), Multi-line (/* */), Documentation (/** */).
While Java Program Structure and Basics gives us the theoretical background, Variables, Data Types, and Operators provides the next layer of complexity.

Variables, Data Types, and Operators

Instance vs Local Variables:

  • Instance: Declared inside a class but outside methods. Have default values. Stored on the Heap.
  • Local: Declared inside a method. Must be initialized before use. Stored on the Stack.

Scope & Lifetime: Scope is where a variable is accessible. Lifetime is how long it stays in memory. Dynamic Initialization: Assigning a value to a variable at runtime (e.g., double c = Math.sqrt(a*a + b*b);).

Data Types:

  • Primitive: Built-in (byte, short, int, long, float, double, char, boolean).
  • Reference: Point to objects (Arrays, Strings, Classes).
Example: Operator Precedence: 5 + 3 * 2 % 4 → 5 + ((3 * 2) % 4) → 5 + (6 % 4) → 5 + 2 = 7.
Having established the core principles of Variables, Data Types, and Operators, we now turn our attention to Control Statements and Arrays.

Control Statements and Arrays

Control Statements:

  • Conditional: if-else, switch-case, ternary operator (condition ? true_val : false_val).
  • Loops: for (known iterations), while (unknown iterations, check before executing), do-while (executes at least once).
  • Jump: break (exits loop), continue (skips current iteration).

Arrays: Contiguous memory holding elements of the same type. Can be 1D (int[] a) or 2D (int[][] matrix).

Example: int[] marks = {90, 85, 88, 92, 95}; int sum = 0; for(int m : marks) sum += m; double avg = sum/5.0;

Unit II: Object-Oriented Programming (OOP) Deep Dive

OOP Pillars, Classes, and Objects

Six Pillars of OOP: Class, Object, Encapsulation, Abstraction, Inheritance, Polymorphism.

  • Class: A blueprint or template.
  • Object: An instance of a class occupying memory.
  • Encapsulation: Wrapping data and methods into a single unit (class).
  • Abstraction: Hiding implementation details and showing only functionality.
  • Inheritance: Acquiring properties of another class.
  • Polymorphism: One interface, multiple forms (overloading/overriding).

new Keyword: Used to allocate memory for an object at runtime. Objects are stored in the Heap memory.

Building on our understanding of OOP Pillars, Classes, and Objects, let's dive into Memory Management and Access Modifiers.

Memory Management and Access Modifiers

Stack vs Heap:

  • Stack: Stores local variables and method calls. Fast access, LIFO.
  • Heap: Stores objects and instance variables. Globally accessible, garbage collected.

Default Values: int (0), double (0.0), char (\u0000), boolean (false), object (null).

Access Modifiers:

  • private: Accessible only within the same class.
  • default: Accessible within the same package.
  • protected: Accessible within the package and subclasses outside the package.
  • public: Accessible everywhere.
To fully appreciate Constructors and the 'this' Keyword, we must apply what we just learned about Memory Management and Access Modifiers.

Constructors and the 'this' Keyword

Constructor: A special method used to initialize objects. Rules: Must have the same name as the class, no return type.

  • Default vs Parameterized: Default has no arguments; parameterized takes arguments to set specific values.
  • Constructor Overloading: Multiple constructors with different parameter lists. Differentiated by compiler based on number/type of arguments.
  • Constructor Chaining: Calling one constructor from another using this() (same class) or super() (parent class).

this Keyword: Refers to the current object. Uses: 1) Resolve variable shadowing. 2) Call another constructor via this(). 3) Pass current object as argument. 4) Return current object.

Moving forward from Constructors and the 'this' Keyword, let's break down the mechanics of Wrapper Classes, Autoboxing, and Strings.

Wrapper Classes, Autoboxing, and Strings

Wrapper Classes: Convert primitives to objects (e.g., char → Character, int → Integer). Methods in Character: isLetter(), isDigit(), isUpperCase().

  • Autoboxing: Automatic conversion of primitive to wrapper.
  • Unboxing: Automatic conversion of wrapper to primitive.

String Class: Strings are immutable (cannot be changed once created). Benefits: Thread safety, caching (String Constant Pool). Ways to create: String s = "A"; (Literal pool) vs String s = new String("A"); (Heap).

== compares memory addresses (reference equality). equals() compares actual string content (value equality).

StringBuffer vs StringBuilder: Both are mutable. StringBuffer is synchronized (thread-safe, slower). StringBuilder is non-synchronized (not thread-safe, faster). Key methods: append(), insert(), replace(), delete(), reverse().

Unit III: Advanced OOP Concepts and Packages

Packages and Generics

Java Package: A grouping of related types (classes, interfaces). Examples: java.util, java.io. Types: Built-in (Java API) and User-defined. The import statement brings package members into visibility.

Generics: Parameterized types for type safety and code reusability. Examples: T (Type), E (Element), K (Key), V (Value).

Example: ArrayList<String> list = new ArrayList<>(); Operations: add(), remove(), get(), size().
Building on our understanding of Packages and Generics, let's dive into Inheritance and the 'super' Keyword.

Inheritance and the 'super' Keyword

Inheritance: Mechanism where one class acquires properties of another. Types: Single, Multilevel, Hierarchical, Hybrid. Multiple inheritance is supported via interfaces.

super Keyword: Refers to the immediate parent class object. Uses: 1) Access parent instance variables. 2) Invoke parent methods. 3) Invoke parent constructor via super().

Transitioning from Inheritance and the 'super' Keyword, we now examine Polymorphism, Overloading vs Overriding, Object Casting, which builds upon these foundational rules.

Polymorphism, Overloading vs Overriding, Object Casting

Polymorphism: Ability to take many forms. Types: Compile-time (Method Overloading) and Run-time (Method Overriding).

  • Method Overloading: Same method name, different parameters (Compile-time).
  • Method Overriding: Same method name and signature in child class (Run-time).

Dynamic Binding (Late Binding): Method calls are resolved at runtime based on the actual object type, not the reference type.

Object Casting:

  • Upcasting: Child to Parent (implicit).
  • Downcasting: Parent to Child (explicit).

instanceof Operator: Used to check if an object is an instance of a specific class. Crucial before downcasting to avoid ClassCastException.

While Polymorphism, Overloading vs Overriding, Object Casting gives us the theoretical background, Abstraction and the Object Class provides the next layer of complexity.

Abstraction and the Object Class

Abstract Class vs Interface:

  • Abstract Class: Can have abstract (no body) and concrete methods. Cannot be instantiated.
  • Interface: 100% abstract (prior to Java 8 default methods). Supports multiple inheritance.

Object Class: The root class of all classes in Java.

  • toString(): Returns string representation of object.
  • equals(): Compares object equality.
  • hashCode(): Returns integer hash value.
  • getClass(): Returns runtime class object.

Unit V: Garbage Collection and Finalization

Garbage Collection (GC)

Garbage Collection: The process by which Java automatically reclaims memory by deleting objects that are no longer reachable.

  • An object is eligible for GC when it loses all references (e.g., set to null, reference reassigned, or block execution ends).

Finalization: The finalize() method is called by the garbage collector on an object when GC determines no more references exist. Deprecated in modern Java due to unreliability and performance hits.

Modern Alternatives: Instead of finalize(), use try-with-resources (AutoCloseable) or the java.lang.ref.Cleaner API to ensure resources are released reliably.
