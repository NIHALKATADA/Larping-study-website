Bytecode, and why is Java considered platform-independent

Bytecode is a highly optimized set of instructions generated by the Java compiler (javac) after compiling the source code. It is not machine code, but rather intermediate code.

Java is platform-independent because the compiler generates this bytecode instead of native machine code. This bytecode can be executed on any operating system as long as that system has a JVM (Java Virtual Machine) installed to interpret it (Write Once, Run Anywhere).

Java's platform independence

Java's "Write Once, Run Anywhere" capability relies on its two-step execution process:

  1. Compilation: The developer writes Program.java (Source Code). The Java Compiler (javac) compiles this into Program.class. Instead of compiling it into machine-specific code (like C++), it compiles it into Bytecode. This bytecode is entirely independent of the underlying OS or hardware.
  2. Execution: The compiled bytecode is transported to any machine (Windows, Mac, Linux). That machine must have a JVM (Java Virtual Machine) installed. The JVM reads the bytecode and translates it into the specific machine-level instructions native to that exact operating system.

Therefore, while the JVM is platform-dependent, the Java program (bytecode) itself is totally platform-independent.

Class and what is an object in Java

A class is a user-defined blueprint or prototype from which objects are created. An object is a runtime instance of a class that has state and behavior.

Difference: A class is a logical entity that consumes no memory upon declaration, whereas an object is a physical entity that consumes memory space in the heap when instantiated.

Purpose of the new keyword in Java

The new keyword in Java is used to create a new object or array by allocating memory at runtime. It essentially instantiates a class.

Storage: The newly created object is always stored in the Heap memory.

Constructor in Java

A constructor is a special block of code that is called automatically when an object is instantiated. It is used to initialize the state of the object.

Rules:

  1. The constructor name must exactly match the class name.
  2. A constructor must not have an explicit return type (not even void).

Constructor overloading

Constructor Overloading is a technique of having more than one constructor in a class with different parameter lists. It allows objects to be initialized in different ways.

The compiler distinguishes them based on the number of parameters, the types of the parameters, and the order of the parameters.

Constructor chaining

Constructor chaining is the process of calling one constructor from another constructor with respect to the current object. It helps avoid duplicate code.

The two keywords used are:

  • this(): Used to call a constructor of the same class.
  • super(): Used to call a constructor of the superclass (parent class).

Autoboxing and unboxing in Java

  • Autoboxing: The automatic conversion that the Java compiler makes between the primitive types and their corresponding object wrapper classes (e.g., converting int to Integer).
  • Unboxing: The reverse process; converting an object of a wrapper type back to its corresponding primitive value (e.g., converting Integer to int).

String immutability

String immutability means that once a String object is created, its value or state cannot be changed. Any operation that alters the string creates a brand new String object rather than modifying the original.

Benefit: It makes Strings thread-safe and allows caching in the String Constant Pool, which saves memory.

Garbage Collection & Memory Tuning

Garbage Collection (GC) is the process by which Java programs perform automatic memory management, freeing up the heap by deleting objects that are no longer in use.

An object becomes eligible for garbage collection when it is completely unreferenced (i.e., no live thread can access it). This happens if its reference is set to null, if it is created anonymously, or if references are reassigned.

A Java package is a mechanism for organizing related classes and interfaces into a single namespace. It prevents naming conflicts and controls access (encapsulation).

  • java.lang (Contains core classes like String, Math. It is imported automatically)

Inheritance

Inheritance is a mechanism where a new class acquires the properties and methods of an existing class, establishing an IS-A relationship and promoting code reuse.

Types supported in Java (via classes):

  • Single Inheritance
  • Multilevel Inheritance
  • Hierarchical Inheritance

Object class

The Object class (located in the java.lang package) is the root class of the Java class hierarchy. Every class in Java directly or indirectly inherits from the Object class.

Two Methods:

  • toString()
  • equals(Object obj)

Polymorphism

Polymorphism is the ability of an object or method to take on many forms, allowing the same interface to be used for different underlying forms (data types).

Two Types:

  1. Compile-time Polymorphism (Static binding, e.g., Method Overloading).
  2. Run-time Polymorphism (Dynamic binding, e.g., Method Overriding).

Dynamic binding

Dynamic Binding is the process where the compiler does not resolve the method call at compile time, but rather the JVM determines the actual method implementation to execute at runtime based on the actual object type.

It is called late binding because the binding of the method call to the method body is delayed until the program is actually executing.

Upcasting and downcasting in Java

  • Upcasting: Casting a subclass reference variable to a superclass reference. This is done automatically and implicitly by the compiler.
  • Downcasting: Casting a superclass reference variable back to a subclass reference. This must be done explicitly by the programmer and requires checking to prevent ClassCastException.

Purpose of the instanceof operator

The instanceof operator is a binary operator used to test whether a given object is an instance of a specific class, subclass, or interface. It returns true or false.

It is primarily used to check object types before attempting a downcast, preventing runtime exceptions.

Abstract class

  • Abstract Class: A class declared with the abstract keyword that cannot be instantiated. It can contain both abstract methods (without a body) and concrete methods.
  • Interface: A completely "abstract class" that acts as a contract. In modern Java, it primarily contains abstract methods and static constants, though it can now have default methods. A class implements an interface.

Single, multilevel, hierarchical, and hybrid inheritance ...

  • Single: Class B inherits from Class A. (Dog inherits Animal)
  • Multilevel: Class C inherits from Class B, which inherits from Class A. (Puppy inherits Dog inherits Animal)
  • Hierarchical: Multiple classes inherit from a single Class A. (Dog and Cat both inherit Animal)
  • Hybrid: A combination of two or more types. In Java, true hybrid inheritance involving multiple parents is only achievable via Interfaces to avoid the Diamond Problem.

Three major uses of the super keyword with suitable examples

  1. Invoke Parent Constructor: super(); (Must be the first line in the child constructor).
  2. Invoke Parent Method: Used when the child has overridden the method. super.display();
  3. Access Parent Variable: Used when the child class hides a parent's variable with the same name. System.out.println(super.x);

Compile-time and run-time polymorphism in Java

  • Compile-time Polymorphism: Achieved through Method Overloading. The compiler knows exactly which method to call based on the method signature (number and type of arguments). Fast execution because binding happens early.
  • Run-time Polymorphism: Achieved through Method Overriding. A parent reference points to a child object. The JVM determines which overridden method to execute during runtime based on the actual object type, not the reference type.

Dynamic binding

Dynamic Binding occurs when the compiler cannot determine the method implementation at compile time, so the JVM resolves it during execution.

class Vehicle {
    void move() { System.out.println("Moving"); }
}
class Car extends Vehicle {
    @Override
    void move() { System.out.println("Driving on wheels"); }
}

public class Main {
    public static void main(String[] args) {
        Vehicle v = new Car(); // Superclass ref, Subclass object
        v.move(); // Outputs: Driving on wheels
    }
}

At compile time, the compiler ensures move() exists in Vehicle. At runtime, the JVM notices the object is actually a Car and executes the overridden version.

Collections Internals (HashMap)

HashMap computes the hash of the key to find the bucket array index. If collisions occur, it forms a LinkedList. To prevent DoS attacks via collision degradation, Java 8 introduced the Treeification Threshold (8), transforming lists into Red-Black Trees for O(log n) lookup.

Map<String, Integer> map = new HashMap<>();
map.put("Key", 1); // Uses hashCode() and equals()
Pro Tip: ConcurrentHashMap. Instead of locking the entire map (like HashTable), ConcurrentHashMap uses CAS (Compare-And-Swap) operations and synchronizes only the specific node (bucket) being updated, allowing high concurrency.

Lambdas & Streams API

Streams enable declarative data processing. Intermediate operations (filter, map) are lazy and do nothing until a Terminal operation (collect, reduce) is invoked. Lambdas (->) implement Functional Interfaces (SAM: Single Abstract Method).

List<Integer> evens = list.stream()
    .filter(n -> n % 2 == 0) // Lazy Intermediate
    .collect(Collectors.toList()); // Terminal Execution
Pro Tip: invokedynamic. Lambdas are NOT anonymous inner classes. The compiler uses the invokedynamic bytecode instruction to generate the lambda implementation dynamically at runtime, heavily optimizing memory and class-loading overhead.

String Pool & Immutability

The String class represents an array of characters. Strings are immutable; once created, their value cannot change.

  • Literals vs New: String s1 = "Java"; creates/reuses a string in the highly-efficient String Constant Pool. String s2 = new String("Java"); forces a new allocation in the normal Heap.
  • == vs equals(): s1 == s2 compares memory addresses (returns false here). s1.equals(s2) compares the actual text characters (returns true).
  • Methods: length(), substring(start, end), toUpperCase(), concat(str).

Garbage Collection and finalization in Java

Garbage Collection automatically deallocates memory for objects that are no longer reachable.

  • Eligibility: An object is eligible if its reference is set to null, reassigned, or created anonymously.
  • finalize(): A method in the Object class historically called by the GC just before destroying the object to release non-Java resources.
  • Deprecation: finalize() was deprecated in Java 9 because it is unpredictable, impacts performance, and can cause memory leaks if implemented poorly.
  • Modern Alternatives: Use try-with-resources (implementing AutoCloseable) for deterministic resource cleanup, or the java.lang.ref.Cleaner API.
