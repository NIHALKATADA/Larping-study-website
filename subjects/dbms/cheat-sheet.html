Keys in Relational Model U1

Super Key
Any combination identifying a row.
Candidate Key
Minimal super key (no redundant columns).
Primary Key (PK)
Chosen candidate key. Unique, NOT NULL.
Foreign Key (FK)
Refers to PK in another table.

Aggregates & Group By U2

SELECT Dept, COUNT(*), AVG(Salary)
FROM Employees
WHERE Status = 'Active'
GROUP BY Dept
HAVING COUNT(*) > 5
ORDER BY Dept DESC;

Note: WHERE filters rows before grouping; HAVING filters after grouping.

Views U2

Virtual tables based on queries. Do not store data directly (usually).

CREATE VIEW HighEarners AS
SELECT Name, Salary 
FROM Employee WHERE Salary > 90000;

Unit III: Structured Query Language (SQL) CO3

DDL (Data Definition) U3

CREATE TABLE Students (
  ID INT PRIMARY KEY,
  Email VARCHAR(50) UNIQUE NOT NULL,
  Age INT CHECK (Age >= 18),
  DeptID INT,
  FOREIGN KEY (DeptID) REFERENCES Dept(ID)
);

DML (Data Manipulation) U3

-- Insert
INSERT INTO Tbl (Col1, Col2) VALUES (1, 'A');

-- Update
UPDATE Tbl SET Col2 = 'B' WHERE Col1 = 1;

-- Delete
DELETE FROM Tbl WHERE Col1 = 1;

TCL (Transaction Control) U3

COMMIT
Save changes permanently.
ROLLBACK
Undo changes to last commit.
SAVEPOINT
Set a marker for partial rollback.
SAVEPOINT SP1;
ROLLBACK TO SP1;

Triggers & Procedures U3

Stored Procedure
Precompiled block of SQL to run logic via CALL/EXEC.
Trigger
Auto-executes BEFORE or AFTER an INSERT/UPDATE/DELETE event.
Cursor
Allows row-by-row iteration in PL/SQL logic.

Unit IV: Transaction Processing CO4

ACID Properties U4

Atomicity
All or nothing (Commit/Rollback).
Consistency
Transforms DB from one valid state to another.
Isolation
Concurrent txns do not interfere.
Durability
Committed data is saved permanently.

Concurrency Control (Locks) U4

  • Shared Lock (S): Allows reading. Multiple txns can hold S locks on same item.
  • Exclusive Lock (X): Allows reading & writing. Only one txn can hold X lock.

Two-Phase Locking (2PL): Growing Phase (acquire locks) → Shrinking Phase (release locks). Guarantees serializability.

Indexing (B & B+ Trees) U4

Deadlocks & Recovery U4

Wait-For Graph
Used to detect deadlocks (cycles = deadlock).
Log-based Recovery
Uses Write-Ahead Logging (WAL). REDO applied for committed, UNDO applied for failed txns.
Checkpoints
Saves state to disk to reduce recovery time.

Unit V: Advanced DB & MongoDB CO5

RDBMS vs NoSQL U5

MongoDB Architecture U5

  • Database → Contains Collections.
  • Collection → Group of Documents (like Table).
  • Document → JSON/BSON object (like Row).
  • Field → Key-value pair (like Column).
  • _id → Unique primary key for every document.

Mongo CRUD Syntax U5

// Insert
db.users.insertOne({ name: "Alice", age: 22 })

// Find (Select)
db.users.find({ age: { $gt: 20 } })

// Update
db.users.updateOne(
  { name: "Alice" }, 
  { $set: { age: 23 } }
)

// Delete
db.users.deleteOne({ name: "Alice" })

Aggregation & Replication U5

Pipeline
Stages for processing data: $match → $group → $sort
Replica Set
Group of mongod instances holding same data set. 1 Primary (writes), N Secondaries (reads/failover).
