Unit I: Java Basics

Programming paradigm and name any two programming paradigms other than OOP

A programming paradigm is a fundamental style or approach to programming, dictating how tasks are structured and executed.

Two other paradigms besides Object-Oriented Programming (OOP) are:

  • Procedural Programming (e.g., C)
  • Functional Programming (e.g., Haskell, LISP)
When was Java officially announced by Sun Microsystems, and what was its original name

Java was officially announced by Sun Microsystems in 1995. Its original name during development was Oak (named after an oak tree outside James Gosling's office).

JDK, JRE, and JVM
  • JDK (Java Development Kit): A full software development environment. It contains the JRE plus development tools like the compiler (javac) and debugger.
  • JRE (Java Runtime Environment): The environment required to run Java programs. It contains the JVM and core class libraries.
  • JVM (Java Virtual Machine): An abstract machine that executes Java Bytecode. It makes Java platform-independent.
Bytecode, and why is Java considered platform-independent

Bytecode is a highly optimized set of instructions generated by the Java compiler (javac) after compiling the source code. It is not machine code, but rather intermediate code.

Java is platform-independent because the compiler generates this bytecode instead of native machine code. This bytecode can be executed on any operating system as long as that system has a JVM (Java Virtual Machine) installed to interpret it (Write Once, Run Anywhere).

Method overloading and method overriding
  • Method Overloading: Creating multiple methods in the same class with the same name but different parameters (compile-time polymorphism).
  • Method Overriding: Providing a specific implementation in a subclass for a method that is already defined in its parent class. The method signature must be identical (run-time polymorphism).
Top-Down and Bottom-Up approaches

Top-Down Approach: The problem is broken down into smaller sub-problems. It focuses on the main algorithm first, then the details (used in Procedural Programming like C).
Example: Building a car by first designing the full car, then breaking it down into engine, wheels, and doors.

Bottom-Up Approach: The smaller modules or objects are designed first, and then integrated together to form the complete system (used in Object-Oriented Programming like Java).
Example: Designing the engine, wheels, and doors first as independent objects, then assembling them to build the car.

Java evolved from Oak and mention any three important features of Java

Java was originally developed by James Gosling at Sun Microsystems in 1991 for interactive television and consumer electronics. It was initially named Oak. It was later renamed Java in 1995 and shifted focus to the World Wide Web because of its platform independence.

Three Important Features:

  • Platform Independent: Write once, run anywhere (WORA) using Bytecode and JVM.
  • Object-Oriented: Everything is an object; follows OOP principles strictly.
  • Robust & Secure: Strong memory management, automatic garbage collection, and no explicit pointers.
Role of JDK, JRE, and JVM in executing a Java program
  • JDK (Java Development Kit): The complete toolbox for a developer. It provides the compiler (javac) which translates the .java source code into a .class file (bytecode).
  • JRE (Java Runtime Environment): The environment where the Java program runs. It provides the core class libraries and packages required for execution.
  • JVM (Java Virtual Machine): The core engine inside the JRE. It reads the bytecode line by line, interprets it, and executes it on the host operating system.

  • Lifetime: The duration of time a variable exists in memory during program execution.

Java data types and differentiate between primitive and reference data types

Primitive Data Types: Predefined by Java and hold actual values. There are 8: byte, short, int, long, float, double, char, boolean. They are stored in stack memory and have a fixed size.

Reference Data Types: User-defined (except Arrays and Strings) and hold references (memory addresses) to the actual objects. They are stored in heap memory. Examples: Classes, Interfaces, Arrays.

One-dimensional and two-dimensional arrays, and differentiate between for, while, and do-while loops

Arrays:

  • 2D Array: An array of arrays (a matrix). int[][] matrix = new int[3][3];

Loops:

  • for: Used when the number of iterations is known in advance.
  • while: Used when iterations are unknown; condition is checked before execution (entry-controlled).
  • do-while: Condition is checked after execution (exit-controlled); guarantees execution at least once.

Java's platform independence in detail, from source code compilation to bytecode execution through the JVM

Java's "Write Once, Run Anywhere" capability relies on its two-step execution process:

  1. Compilation: The developer writes Program.java (Source Code). The Java Compiler (javac) compiles this into Program.class. Instead of compiling it into machine-specific code (like C++), it compiles it into Bytecode. This bytecode is entirely independent of the underlying OS or hardware.
  2. Execution: The compiled bytecode is transported to any machine (Windows, Mac, Linux). That machine must have a JVM (Java Virtual Machine) installed. The JVM reads the bytecode and translates it into the specific machine-level instructions native to that exact operating system.

Therefore, while the JVM is platform-dependent, the Java program (bytecode) itself is totally platform-independent.

Data Types: Primitives (int x = 5;) and References (String s = "Hi";).
Arrays: Homogeneous collections. int[] arr = {1, 2, 3};
Operators: Arithmetic (+, -), Relational (>, ==), Logical (&&, ||).

  3. 6 % 4 = 2 (Remainder of 6 divided by 4)
  4. 5 + 2 = 7

Unit II: OOP Concepts

Object-Oriented Programming and list the six pillars of OOP

Object-Oriented Programming (OOP) is a paradigm centered around "objects" (which contain data in the form of fields and code in the form of methods) rather than "actions" or logic.

The six pillars (or core concepts) of OOP are:

  1. Class
  2. Object
  3. Encapsulation
  4. Abstraction
  5. Inheritance
  6. Polymorphism

Example: If Car is a class (the blueprint), then a Red Tesla Model S is an object (an actual car).

Encapsulation, abstraction, inheritance, and polymorphism
  • Encapsulation: Wrapping data (variables) and code (methods) together into a single unit (class), protecting the data from outside interference.
  • Abstraction: Hiding internal implementation details and exposing only the necessary functionalities to the user.
  • Inheritance: A mechanism where a new class (child) inherits properties and behaviors from an existing class (parent), promoting code reusability.
  • Polymorphism: The ability of a single entity (method, object, or operator) to take on multiple forms and behave differently based on the context.
List the four access modifiers in Java and state the default access level

The four access modifiers in Java (from most restrictive to least) are:

  1. private (accessible only within the same class)
  2. default (no keyword; accessible only within the same package)
  3. protected (accessible within the same package and subclasses in other packages)
  4. public (accessible from anywhere)

If no modifier is specified, the access level is default (package-private).

Class and what is an object in Java

A class is a user-defined blueprint or prototype from which objects are created. An object is a runtime instance of a class that has state and behavior.

Difference: A class is a logical entity that consumes no memory upon declaration, whereas an object is a physical entity that consumes memory space in the heap when instantiated.

Purpose of the new keyword in Java

The new keyword in Java is used to create a new object or array by allocating memory at runtime. It essentially instantiates a class.

Storage: The newly created object is always stored in the Heap memory.

Constructor in Java

A constructor is a special block of code that is called automatically when an object is instantiated. It is used to initialize the state of the object.

Rules:

  1. The constructor name must exactly match the class name.
  2. A constructor must not have an explicit return type (not even void).
Constructor overloading

Constructor Overloading is a technique of having more than one constructor in a class with different parameter lists. It allows objects to be initialized in different ways.

The compiler distinguishes them based on the number of parameters, the types of the parameters, and the order of the parameters.

Constructor chaining

Constructor chaining is the process of calling one constructor from another constructor with respect to the current object. It helps avoid duplicate code.

The two keywords used are:

  • this(): Used to call a constructor of the same class.
  • super(): Used to call a constructor of the superclass (parent class).
Purpose of the this keyword in Java

The this keyword is a reference variable that refers to the current object on which the method or constructor is being invoked.

Two Uses:

  1. To resolve shadowing when instance variables and local parameters share the same name (e.g., this.name = name;).
  2. To invoke another constructor in the same class (using this()).
Autoboxing and unboxing in Java
  • Autoboxing: The automatic conversion that the Java compiler makes between the primitive types and their corresponding object wrapper classes (e.g., converting int to Integer).
  • Unboxing: The reverse process; converting an object of a wrapper type back to its corresponding primitive value (e.g., converting Integer to int).
String immutability

String immutability means that once a String object is created, its value or state cannot be changed. Any operation that alters the string creates a brand new String object rather than modifying the original.

Benefit: It makes Strings thread-safe and allows caching in the String Constant Pool, which saves memory.

Difference between stack and heap memory in Java
  • Heap Memory: This is where all actual objects and instance variables are stored. It is dynamically allocated at runtime when the new keyword is used. It is managed by the Garbage Collector.
  • Stack Memory: This is where all local variables, method calls, and object references are stored. When you write Car c = new Car();, the object itself goes in the heap, but the reference variable c is kept in the stack, pointing to the heap memory address.
Default values of instance variables for int, double, char, boolean, and object reference types

When instance variables are not explicitly initialized, Java assigns them default values:

  • int (and byte, short, long): 0
  • double (and float): 0.0
  • char: '\u0000' (null character)
  • boolean: false
  • Object References (String, arrays, custom classes): null
Default/no-argument and parameterized constructors

Default / No-Argument Constructor: Takes no parameters. If no constructor is defined, the compiler provides one automatically. Used for default initialization.

class Box {
    Box() { System.out.println("Empty box created"); }
}

Parameterized Constructor: Takes parameters to initialize the object with specific values upon creation.

class Box {
    int size;
    Box(int s) { this.size = s; }
}
Constructor overloading

Constructor Overloading allows a class to have multiple constructors with different parameter lists, giving flexibility in how an object is initialized.

class Rectangle {
    int length, width;
    
    // Constructor 1: Default (Square)
    Rectangle() {
        length = 5; width = 5;
    }
    
    // Constructor 2: Parameterized
    Rectangle(int l, int w) {
        length = l; width = w;
    }
}
Constructor overloading and constructor chaining
  • Constructor Overloading: Having multiple separate constructors in the same class to handle different initialization scenarios.
  • Constructor Chaining: The process where one constructor explicitly calls another constructor (either within the same class or from the parent class) to reuse initialization logic.

Keywords for Chaining:

  • this() - Calls another constructor in the same class.
  • super() - Calls a constructor in the parent class.
Any three uses of the this keyword
  1. Resolve Shadowing: Used to distinguish instance variables from local parameters.
    this.name = name;
  2. Constructor Chaining: Used to invoke another constructor in the same class.
    this(10); // Calls parameterized constructor
  3. Pass as Argument: Used to pass the current object as a parameter to another method.
    helper.printDetails(this);
Private, default, protected, and public access modifiers in Java
  • Private: The most restrictive. Accessible only within the class where it is declared. Used for data hiding.
  • Default: (No keyword). Accessible only by classes within the same package.
  • Protected: Accessible within the same package, and by subclasses located in other packages.
  • Public: The least restrictive. Accessible from any class anywhere in the program.
Character wrapper class and any four useful methods of the Character class

The Character class (in java.lang) wraps a primitive char value in an object. It provides numerous utility methods for character manipulation.

Four Useful Methods:

  • Character.isLetter(ch): Returns true if the character is a letter.
  • Character.isDigit(ch): Returns true if the character is a number.
  • Character.isUpperCase(ch): Returns true if the character is uppercase.
  • Character.toLowerCase(ch): Converts the character to lowercase.
Two ways of creating a String in Java:
  • String Literal: String s = "Hello";
    The JVM first checks the String Constant Pool. If "Hello" exists, it returns the reference. If not, it creates it. This is highly memory-efficient.
  • new Keyword: String s = new String("Hello");
    The JVM forces the creation of a brand new String object in the Heap memory, bypassing the pool entirely, even if "Hello" already exists in the pool.
= = and equals() when comparing String objects

  • equals() Method: Compares the actual contents/values of the two objects for logical equality.

Six pillars of OOP—class, object, encapsulation, abstraction, inheritance, and polymorphism—with suitable examples

Classes and Objects in Java in detail

A Class is a blueprint. An Object is a physical instance. The new keyword allocates distinct heap memory for every object created.

Because each object gets its own memory block in the heap, they maintain independent copies of instance variables. Changing the variable in one object does not affect the other.

}
public class Main {

        Account acc2 = new Account();
        
        acc1.balance = 500;
        acc2.balance = 1000;
        // acc1 and acc2 are independent.
    }
}

Constructors in Java in detail

Constructors are special blocks invoked when an object is instantiated via new.

Constructor overloading and constructor chaining in Java

Overloading allows a class to have multiple constructors with different parameters. Chaining allows these constructors to call each other, or call the parent's constructor, to avoid duplicating initialization logic.

class Parent {
    Parent() { System.out.println("Parent init"); }
}
class Child extends Parent {
    int x, y;
    
    Child() {
        this(0, 0); // Constructor Chaining via this()
    }
    
    Child(int x, int y) { // Overloaded constructor
        super(); // Constructor Chaining via super() to Parent
        this.x = x;
        this.y = y;
    }
}

  4. Passing as Argument: Passing the current instance to an event listener: button.addListener(this);
  5. Returning: Used in builder patterns to chain method calls: return this;

Unit III: Inheritance & Exceptions

Java package

A Java package is a mechanism for organizing related classes and interfaces into a single namespace. It prevents naming conflicts and controls access (encapsulation).

Two Examples:

  • java.util (Contains utility classes like Scanner, ArrayList)
  • java.lang (Contains core classes like String, Math. It is imported automatically)
Inheritance

Inheritance is a mechanism where a new class acquires the properties and methods of an existing class, establishing an IS-A relationship and promoting code reuse.

Types supported in Java (via classes):

  • Single Inheritance
  • Multilevel Inheritance
  • Hierarchical Inheritance

(Note: Multiple and Hybrid inheritance are not supported through classes, only through interfaces).

Purpose of the super keyword

The super keyword is a reference variable used to refer to the immediate parent class object.

Two Uses:

  1. To invoke the immediate parent class constructor (e.g., super();).
  2. To invoke an overridden method in the parent class (e.g., super.display();).
Object class

The Object class (located in the java.lang package) is the root class of the Java class hierarchy. Every class in Java directly or indirectly inherits from the Object class.

Two Methods:

  • toString()
  • equals(Object obj)
Polymorphism

Polymorphism is the ability of an object or method to take on many forms, allowing the same interface to be used for different underlying forms (data types).

Two Types:

  1. Compile-time Polymorphism (Static binding, e.g., Method Overloading).
  2. Run-time Polymorphism (Dynamic binding, e.g., Method Overriding).
Dynamic binding

Dynamic Binding is the process where the compiler does not resolve the method call at compile time, but rather the JVM determines the actual method implementation to execute at runtime based on the actual object type.

It is called late binding because the binding of the method call to the method body is delayed until the program is actually executing.

Upcasting and downcasting in Java
  • Upcasting: Casting a subclass reference variable to a superclass reference. This is done automatically and implicitly by the compiler.
  • Downcasting: Casting a superclass reference variable back to a subclass reference. This must be done explicitly by the programmer and requires checking to prevent ClassCastException.
Purpose of the instanceof operator

The instanceof operator is a binary operator used to test whether a given object is an instance of a specific class, subclass, or interface. It returns true or false.

It is primarily used to check object types before attempting a downcast, preventing runtime exceptions.

Abstract class
  • Abstract Class: A class declared with the abstract keyword that cannot be instantiated. It can contain both abstract methods (without a body) and concrete methods.
  • Interface: A completely "abstract class" that acts as a contract. In modern Java, it primarily contains abstract methods and static constants, though it can now have default methods. A class implements an interface.
Generics in Java

Generics enable types (classes and interfaces) to be parameters when defining classes, interfaces and methods. This provides stronger type checks at compile time and removes the need for explicit casting.

Example: <T> is a generic type parameter where T stands for Type. Example usage: List<String> list = new ArrayList<String>();

Built-in and user-defined packages
  • Built-in Packages: Provided by the Java API. Example: java.util, java.io.
  • User-defined Packages: Created by the programmer to group related classes. Example: package com.mycompany.utils;

Import Statement: Used to bring a class or an entire package into visibility so it can be used without typing its fully qualified name (e.g., import java.util.Scanner;).

Single, multilevel, hierarchical, and hybrid inheritance
  • Single: Class B inherits from Class A. (Dog inherits Animal)
  • Multilevel: Class C inherits from Class B, which inherits from Class A. (Puppy inherits Dog inherits Animal)
  • Hierarchical: Multiple classes inherit from a single Class A. (Dog and Cat both inherit Animal)
  • Hybrid: A combination of two or more types. In Java, true hybrid inheritance involving multiple parents is only achievable via Interfaces to avoid the Diamond Problem.
Three major uses of the super keyword
  1. Invoke Parent Constructor: super(); (Must be the first line in the child constructor).
  2. Invoke Parent Method: Used when the child has overridden the method. super.display();
  3. Access Parent Variable: Used when the child class hides a parent's variable with the same name. System.out.println(super.x);
Object class and the purpose of toString(), equals(), hashCode(), and getClass()

The Object class is the universal superclass of all Java classes.

  • toString(): Returns a string representation of the object (often overridden to show field values).
  • equals(): Used to compare the logical equality of two objects.
  • hashCode(): Returns an integer hash code value for the object, crucial for collections like HashMap.
  • getClass(): Returns the runtime class object of the current instance (used in reflection).

Compile-time and run-time polymorphism in Java
  • Compile-time Polymorphism: Achieved through Method Overloading. The compiler knows exactly which method to call based on the method signature (number and type of arguments). Fast execution because binding happens early.
  • Run-time Polymorphism: Achieved through Method Overriding. A parent reference points to a child object. The JVM determines which overridden method to execute during runtime based on the actual object type, not the reference type.
Dynamic binding and object casting

Dynamic Binding is resolving a method call at runtime depending on the actual object.

  • Upcasting: Casting a subclass to a superclass. It is automatic. Animal a = new Dog(); This triggers dynamic binding when overridden methods are called.
  • Downcasting: Casting a superclass back to a subclass. It must be explicit. Dog d = (Dog) a; This is needed to access methods specific only to the child class.
Instanceof operator and its importance before performing downcasting

The instanceof operator checks if an object is an instance of a specific class or interface.

Importance in Downcasting: Downcasting a parent reference to a child reference is dangerous because if the parent reference doesn't actually hold that specific child object, the JVM throws a ClassCastException. Using if (obj instanceof Dog) { Dog d = (Dog) obj; } ensures the downcast is mathematically safe.

Generics and their advantages

Generics allow classes, interfaces, and methods to operate on specified data types as parameters, providing compile-time type safety.

Advantages: Prevents ClassCastException at runtime and eliminates the need for manual type-casting.

Common Parameters:

  • T: Type (General)
  • E: Element (Used heavily in Collections like ArrayList)
  • K: Key (Used in Maps)
  • V: Value (Used in Maps)
ArrayList and packages in Java

ArrayList: A resizable-array implementation of the List interface found in java.util. Unlike standard arrays, it grows and shrinks dynamically.

Common Operations: add(), remove(), get(), size().

Packages: Containers that group related classes and interfaces together.

Purpose: To prevent naming conflicts, group related code logically, and control access visibility (via package-private modifiers).

All major types of inheritance in Java—single, multilevel, hierarchical, hybrid, and multiple inheritance
  • Single: Class A → Class B
  • Multilevel: Class A → Class B → Class C
  • Hierarchical: Class A → Class B, Class A → Class C
  • Multiple: Class A, Class B → Class C. Not supported directly through classes due to the Diamond Problem.
  • Hybrid: A mix of the above.

Multiple Inheritance via Interfaces: Because interfaces traditionally do not hold implementation or state, a single Java class can implement multiple interfaces without ambiguity over whose method to inherit.

Object class in detail and demonstrate the use of toString(), equals(), hashCode(), and getClass()

The Object class is the root of the class hierarchy.

class Person {
    String name;
    Person(String n) { name = n; }
    
    // Overriding toString
    public String toString() { return "Person: " + name; }
    
    // Overriding equals
    public boolean equals(Object obj) {
        if(obj instanceof Person) {
            return this.name.equals(((Person)obj).name);
        }
        return false;
    }
}

// Usage:
Person p = new Person("John");
System.out.println(p.toString());
System.out.println(p.hashCode());
System.out.println(p.getClass().getName());
Write a Java program to demonstrate method overloading and method overriding
class MathOps {
    // Overloading (Compile-time Polymorphism)
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
}

class Animal {
    void sound() { System.out.println("Generic sound"); }
}
class Dog extends Animal {
    // Overriding (Run-time Polymorphism)
    @Override
    void sound() { System.out.println("Bark"); }
}

Compile-time: The compiler binds the add() method based on the parameter data types provided. Run-time: The JVM binds the sound() method based on whether the actual heap object is an Animal or a Dog.

Dynamic binding in detail

Dynamic Binding occurs when the compiler cannot determine the method implementation at compile time, so the JVM resolves it during execution.

class Vehicle {
    void move() { System.out.println("Moving"); }
}
class Car extends Vehicle {
    @Override
    void move() { System.out.println("Driving on wheels"); }
}

public class Main {
    public static void main(String[] args) {
        Vehicle v = new Car(); // Superclass ref, Subclass object
        v.move(); // Outputs: Driving on wheels
    }
}

At compile time, the compiler ensures move() exists in Vehicle. At runtime, the JVM notices the object is actually a Car and executes the overridden version.

Object casting in Java
class Animal {}
class Dog extends Animal {
    void bark() { System.out.println("Woof"); }
}

public class Main {
    public static void main(String[] args) {
        // Upcasting (Automatic)
        Animal a = new Dog(); 
        
        // Downcasting (Explicit & requires checking)
        if (a instanceof Dog) {
            Dog d = (Dog) a;
            d.bark(); // Safe to call child-specific method
        }
    }
}

Interfaces in Java and compare them

Interfaces define contracts (mostly abstract methods). Unlike Abstract classes which can have state and constructors, interfaces cannot maintain instance state.

interface Printable {
    void print();
}
interface Showable {
    void show();
}

class Document implements Printable, Showable {
    public void print() { System.out.println("Printing"); }
    public void show() { System.out.println("Showing"); }
}

public class Main {
    public static void main(String[] args) {
        Document doc = new Document();
        doc.print();
        doc.show();
    }
}
Generic programming in Java

Generics allow parameters for types, catching type errors at compile-time instead of runtime.

// Generic Class
class Box<T> {
    private T item;
    public void set(T t) { item = t; }
    public T get() { return item; }
}

// Generic Method
public <E> void printArray(E[] array) {
    for(E element : array) { System.out.println(element); }
}

Advantages: Code can be reused for any object type while maintaining rigorous type safety without explicit casting.

Garbage Collection in Java

Garbage Collection (GC) is the process by which Java programs perform automatic memory management, freeing up the heap by deleting objects that are no longer in use.

An object becomes eligible for garbage collection when it is completely unreferenced (i.e., no live thread can access it). This happens if its reference is set to null, if it is created anonymously, or if references are reassigned.

Garbage Collection and finalization in Java

Garbage Collection automatically deallocates memory for objects that are no longer reachable.

  • Eligibility: An object is eligible if its reference is set to null, reassigned, or created anonymously.
  • finalize(): A method in the Object class historically called by the GC just before destroying the object to release non-Java resources.
  • Deprecation: finalize() was deprecated in Java 9 because it is unpredictable, impacts performance, and can cause memory leaks if implemented poorly.
  • Modern Alternatives: Use try-with-resources (implementing AutoCloseable) for deterministic resource cleanup, or the java.lang.ref.Cleaner API.
