Unit I: Java Basics

Programming Paradigms

Programming paradigms define the style of structuring and executing code.

  • Procedural Programming (POP): Top-down approach, divides code into functions, less secure data.
  • Object-Oriented Programming (OOP): Bottom-up approach, divides code into objects, secure and encapsulated data.
With Programming Paradigms in mind, we can see why Java Fundamentals becomes crucial in this context.

Java Fundamentals

Java evolved from Oak to become a robust, platform-independent language.

  • History: Announced in 1995 by Sun Microsystems; originally named Oak.
  • Key Features: Platform-independent, object-oriented, robust, and secure.
  • Platform Independence: The compiler generates intermediate Bytecode, which can be executed on any OS with a JVM.
With Java Fundamentals in mind, we can see why Execution Environment (JDK, JRE, JVM) becomes crucial in this context.

Execution Environment (JDK, JRE, JVM)

Java relies on three core components for development and execution.

  • JDK (Java Development Kit): Complete toolbox containing the JRE and development tools like the compiler (javac).
  • JRE (Java Runtime Environment): Environment required to run programs, containing the JVM and core libraries.
  • JVM (Java Virtual Machine): The engine that interprets and executes bytecode line by line.
With Execution Environment (JDK, JRE, JVM) in mind, we can see why Variables and Data Types becomes crucial in this context.

Variables and Data Types

Java is a strongly typed language that supports both primitive and reference data types.

  • Primitive Types: 8 predefined types (byte, short, int, long, float, double, char, boolean) stored in stack memory.
  • Reference Types: User-defined types (Classes, Arrays, Interfaces) pointing to objects stored in heap memory.
  • Variable Scope: Dictates visibility, while lifetime dictates existence in memory.
  • Instance vs Local: Instance variables are declared in the class; local variables in methods/blocks and require initialization.
Having established the core principles of Variables and Data Types, we now turn our attention to Syntax, Arrays, and Control Structures.

Syntax, Arrays, and Control Structures

Java uses a structured syntax and provides standard control flow mechanisms.

  • Naming Rules: Identifiers must start with a letter, _, or $ and are case-sensitive. Follow camelCase and PascalCase conventions.
  • Arrays: Supports 1D (linear list) and 2D (matrix) arrays.
  • Loops: for (known iterations), while (entry-controlled), and do-while (exit-controlled, guarantees one execution).

Unit II: Object-Oriented Programming

OOP Core Concepts

Java is centered around objects and six fundamental OOP pillars.

  • Class vs Object: A class is a logical blueprint; an object is a physical instance allocating heap memory.
  • Encapsulation: Wrapping data and methods into a single unit for protection.
  • Abstraction: Hiding implementation details and exposing necessary functionality.
  • Inheritance & Polymorphism: Promoting code reusability and allowing multiple forms of behavior.
Moving forward from OOP Core Concepts, let's break down the mechanics of Memory Allocation & the 'new' Keyword.

Memory Allocation & the 'new' Keyword

Memory in Java is divided into Heap and Stack for efficient execution.

  • Heap Memory: Dynamically allocates memory for objects and instance variables using the new keyword.
  • Stack Memory: Stores local variables, method calls, and object reference variables.
  • Default Values: Uninitialized instance variables default to 0, 0.0, false, or null depending on type.
Having established the core principles of Memory Allocation & the 'new' Keyword, we now turn our attention to Constructors & Chaining.

Constructors & Chaining

Constructors initialize the state of objects upon creation.

  • Rules: Name must match the class; no return type.
  • Overloading: Multiple constructors differentiated by parameter number, type, or order.
  • Chaining: Calling one constructor from another to avoid duplication using this() (same class) or super() (parent class).
Moving forward from Constructors & Chaining, let's break down the mechanics of The 'this' Keyword.

The 'this' Keyword

The this keyword refers to the current object instance.

  • Resolve Shadowing: Distinguishes instance variables from identically named local parameters.
  • Constructor Chaining: Invokes another constructor in the same class via this().
  • Passing Context: Can be passed as an argument to methods or returned from methods.
Having established the core principles of The 'this' Keyword, we now turn our attention to Access Modifiers.

Access Modifiers

Access modifiers control the visibility of classes, variables, and methods.

  • Private: Accessible only within the same class.
  • Default: Accessible within the same package.
  • Protected: Accessible within the same package and by subclasses in other packages.
  • Public: Accessible from anywhere.
With Access Modifiers in mind, we can see why Strings & Wrapper Classes becomes crucial in this context.

Strings & Wrapper Classes

Java provides special handling for Strings and primitive wrapper classes.

  • String Immutability: Strings cannot be changed once created, enabling memory-saving caching in the String Constant Pool.
  • Comparison: == compares memory references, while equals() compares actual content.
  • Autoboxing/Unboxing: Automatic conversion between primitives and their wrapper classes (e.g., int to Integer).

Unit III: Inheritance & Polymorphism

Inheritance & The 'super' Keyword

Inheritance establishes an IS-A relationship to promote code reuse.

  • Supported Types: Single, Multilevel, and Hierarchical (Multiple inheritance is achieved via Interfaces).
  • super Keyword: Refers to the immediate parent class object.
  • Uses of super: Invokes parent constructors, accesses overridden parent methods, and accesses hidden parent variables.
To fully appreciate Polymorphism & Dynamic Binding, we must apply what we just learned about Inheritance & The 'super' Keyword.

Polymorphism & Dynamic Binding

Polymorphism allows a single entity to exhibit different behaviors based on context.

  • Compile-time (Static): Achieved via Method Overloading (same name, different parameters).
  • Run-time (Dynamic): Achieved via Method Overriding (same signature in subclass).
  • Dynamic Binding: Method calls are resolved at run-time based on the actual object type (Late Binding).
With Polymorphism & Dynamic Binding in mind, we can see why Object Class & Casting becomes crucial in this context.

Object Class & Casting

The Object class is the root of the Java class hierarchy, and casting allows type conversion.

  • Object Methods: Provides foundational methods like toString(), equals(), hashCode(), and getClass().
  • Upcasting: Implicitly casting a subclass reference to a superclass reference.
  • Downcasting: Explicitly casting a superclass reference to a subclass reference, validated safely using instanceof.
With Object Class & Casting in mind, we can see why Abstraction & Interfaces becomes crucial in this context.

Abstraction & Interfaces

Abstract classes and interfaces define contracts and hide implementation details.

  • Abstract Class: Cannot be instantiated; can contain both abstract and concrete methods.
  • Interface: A completely abstract blueprint that classes implement, primarily used to achieve multiple inheritance.
Building on our understanding of Abstraction & Interfaces, let's dive into Packages & Generics.

Packages & Generics

Packages organize code, while generics provide compile-time type safety.

  • Packages: Built-in (e.g., java.util) and user-defined namespaces preventing naming conflicts; imported via the import statement.
  • Generics: Parameterize types (classes/interfaces/methods) to avoid explicit casting and catch errors at compile time.

Unit V: Memory Management

Garbage Collection (GC)

Garbage Collection automatically manages memory by reclaiming unused objects.

  • Mechanism: The JVM periodically frees up heap memory by deleting objects that are no longer referenced.
  • Eligibility: Objects become eligible for GC when their references are nullified, reassigned, or created anonymously.
With Garbage Collection (GC) in mind, we can see why Finalization & Modern Alternatives becomes crucial in this context.

Finalization & Modern Alternatives

Finalization was historically used for cleanup before object destruction.

  • finalize() Method: Called by the GC before destroying an object, but is now deprecated due to unpredictability.
  • Modern Alternatives: try-with-resources and Cleaner are the recommended, safer approaches for resource management.
