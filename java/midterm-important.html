Q120. Given a superclass reference that refers to a subclass object, analyze which overridden method is executed and justify your answer with code.

Unit III CO3 | Bloom L4 5 Marks Midterm Score: 9.7

Analysis & Architectural Justification:

When a superclass reference variable holds a subclass instance, invoking an overridden method causes the subclass's method to execute.

class Base {
    void identify() {
        System.out.println("Inside Base class identification.");
    }
}

class Derived extends Base {
    @Override
    void identify() {
        System.out.println("Inside Derived class identification.");
    }
}

public class DispatchAnalysis {
    public static void main(String[] args) {
        Base ref = new Derived(); // Superclass reference -> Subclass object
        ref.identify();           // Output: Inside Derived class identification.
    }
}

Justification:

  • Reference Type vs Object Type: The reference type (Base) only determines which method names are legally accessible at compile time.
  • Virtual Method Table (vtable): At runtime, the JVM inspects the object header of new Derived() on the heap to find its vtable pointer. The vtable slot for identify() points directly to Derived.identify(), executing the subclass implementation via Late Dynamic Binding.

Quick Recall: The subclass method executes because Java resolves virtual methods at runtime via the heap object's vtable (Dynamic Dispatch).

Superclass reference Subclass object Dynamic Method Dispatch vtable Virtual Method Invocation

Q11. Describe the role of the JVM in running a Java program.

Unit I CO1 | Bloom L2 2 Marks Midterm Score: 9.6

The Java Virtual Machine (JVM) is the abstract computing machine that provides the runtime execution environment for Java applications. Its primary responsibilities include:

  • Class Loading: Loads .class files into memory via the ClassLoader subsystem.
  • Bytecode Verification: Checks bytecode instructions for safety and security violations.
  • Execution & JIT Compilation: Interprets bytecode into native machine code, optimizing hot code blocks using the Just-In-Time (JIT) compiler.
  • Automatic Memory Management: Allocates heap memory for objects and reclaims unreferenced memory via the Garbage Collector.

Quick Recall: The JVM loads class files, verifies bytecode security, executes instructions (via interpreter & JIT compiler), and manages memory via Garbage Collection.

Q31. Explain why Java is called platform independent.

Unit I CO1 | Bloom L2 2 Marks Midterm Score: 9.6

Java is termed platform independent because compiled Java programs can execute on any computer architecture without source-code modification or recompilation, embodying the "Write Once, Run Anywhere" (WORA) philosophy.

This is achieved via a two-step process:

  1. The javac compiler translates source code (.java) into platform-neutral bytecode (.class).
  2. Each target platform has a platform-specific Java Virtual Machine (JVM) that reads and translates this universal bytecode into native machine instructions.

Quick Recall: Java code compiles to universal bytecode, which is run by platform-specific JVMs on Windows, Linux, or Mac without recompiling.

🎯 Evaluator Scoring Keywords:
Platform Independent WORA Bytecode JVM javac compiler

Q8. State what is meant by method overloading.

Method Overloading is a compile-time (static) polymorphism mechanism where a class contains multiple methods sharing the exact same method name, but differentiated by their parameter list signatures.

Differences can include:

  • Number of arguments (e.g., sum(int, int) vs. sum(int, int, int)).

Note: Changing only the return type does not constitute valid method overloading.
