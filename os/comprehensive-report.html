Unit I: OS Basics and Architectures

Introduction & Functions of OS

An Operating System acts as an intermediary between hardware and user applications.

  • Manages CPU scheduling and execution
  • Handles memory allocation and de-allocation
  • Organizes file systems and directories
  • Coordinates I/O devices and drivers
With Introduction & Functions of OS in mind, we can see why Types of Operating Systems becomes crucial in this context.

Types of Operating Systems

Different environments require specialized OS architectures.

  • Batch OS: Executes jobs sequentially without user interaction
  • Multiprogramming: Maximizes CPU utilization by switching jobs during I/O
  • Time-Sharing: Maximizes interactivity with rapid time-slicing
  • Real-Time: Enforces strict deadlines for critical tasks
Building on our understanding of Types of Operating Systems, let's dive into Dual-Mode Operation & Interrupts.

Dual-Mode Operation & Interrupts

Hardware-level protection is achieved by dividing execution privileges.

  • Kernel Mode (0): Full access to privileged instructions and hardware
  • User Mode (1): Restricted access for running application programs
  • Hardware Interrupts: Asynchronous signals from devices (e.g., timers)
  • Software Traps: Synchronous signals from exceptions or system calls
Transitioning from Dual-Mode Operation & Interrupts, we now examine System Calls & I/O Mechanisms, which builds upon these foundational rules.

System Calls & I/O Mechanisms

System calls bridge user space applications and kernel space services.

  • System Call Types: Process control, file management, device management, communications
  • Programmed I/O: High CPU involvement with busy-waiting
  • Interrupt-Driven I/O: CPU handles interrupts after data transfers
  • DMA: Direct bulk transfers bypassing CPU to maximize efficiency
Building on our understanding of System Calls & I/O Mechanisms, let's dive into OS Structural Designs.

OS Structural Designs

OS architecture balances performance with stability and maintainability.

  • Monolithic: High performance but tight coupling risks system crashes
  • Microkernel: High reliability via isolated services but suffers IPC overhead
  • Module-Based (Hybrid): Blends monolithic speed with dynamic loading flexibility

Unit II: Process Management

Process Concepts & PCB

A process is an active program in execution managed via a Process Control Block (PCB).

  • Process States: New, Ready, Running, Waiting (Blocked), Terminated
  • PCB Data: Stores PID, state, program counter, and CPU registers
  • Program vs Process: Passive file on disk vs active entity in memory
Building on our understanding of Process Concepts & PCB, let's dive into Context Switching.

Context Switching

Context switching allows multiple processes to share a single CPU seamlessly.

  • Saves current process state into its PCB
  • Loads new process state from its PCB
  • Triggered by interrupts, time quantum expiration, or blocking system calls
  • Requires kernel intervention and introduces minor overhead
Moving forward from Context Switching, let's break down the mechanics of CPU Schedulers.

CPU Schedulers

Schedulers manage process flow between queues and the CPU.

  • Long-Term (Job): Loads processes into memory; controls multiprogramming degree
  • Short-Term (CPU): Selects ready processes for execution frequently
  • Medium-Term: Swaps processes between disk and memory to relieve pressure
While CPU Schedulers gives us the theoretical background, Scheduling Algorithms provides the next layer of complexity.

Scheduling Algorithms

Algorithms decide CPU allocation based on preemptive or non-preemptive strategies.

  • Non-Preemptive: Process holds CPU until completion (e.g., FCFS)
  • Preemptive: OS forcefully interrupts processes (e.g., Round Robin)
  • Starvation: Low-priority processes wait indefinitely, solved via aging
  • Metrics: Optimizes turnaround time, waiting time, and CPU utilization
Having established the core principles of Scheduling Algorithms, we now turn our attention to Threads & Execution.

Threads & Execution

Threads act as lightweight processes enabling concurrent execution within an application.

  • User Threads: Fast switching, managed by libraries, invisible to kernel
  • Kernel Threads: Slower switching, managed directly by OS, support true parallelism
  • Benefits: Resource sharing, economy, and improved responsiveness

Unit III: Concurrency and Synchronization

Concurrency & Critical Sections

Concurrency requires careful management to prevent race conditions in shared resources.

  • Cooperating Processes: Affect or are affected by other executing processes
  • Critical Section: Code segment where shared variables are modified
  • Atomic Operations: Indivisible instructions essential for safe synchronization
  • Requirements: Mutual exclusion, progress, and bounded waiting
Transitioning from Concurrency & Critical Sections, we now examine Semaphores, which builds upon these foundational rules.

Semaphores

Semaphores are synchronization tools used to control access to shared resources.

  • Binary Semaphores (Mutex): State is 0 or 1, provides mutual exclusion
  • Counting Semaphores: Integer values track multiple available resource instances
  • Operations: wait() decrements, signal() increments the value
  • Issues: Incorrect use can lead to deadlocks or priority inversion
Having established the core principles of Semaphores, we now turn our attention to Monitors & Locks.

Monitors & Locks

High-level synchronization constructs simplify concurrent programming.

  • Mutex Locks: Simple locking mechanisms protecting critical sections
  • Monitors: Abstract data types encapsulating shared data and synchronization
  • Condition Variables: Allow threads to wait for specific state changes
  • Advantage: Reduces human error compared to raw semaphores
Now that we have a solid grasp of Monitors & Locks, the natural next step is to explore Deadlock Basics.

Deadlock Basics

Deadlocks occur when processes indefinitely wait for resources held by each other.

  • Mutual Exclusion: Resources cannot be shared
  • Hold and Wait: Holding resources while requesting more
  • No Preemption: Resources cannot be forcefully taken
  • Circular Wait: A closed chain of waiting processes
