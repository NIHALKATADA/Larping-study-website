Q1. Define Operating System.

Unit I CO1 | Bloom L1 2 Marks Midterm Score: 9.5

An Operating System (OS) is system software that acts as an intermediary between computer hardware and the computer user. It manages hardware resources and provides common services for computer programs, ensuring efficient and convenient execution of user applications.

  • Process Management: Scheduling and execution of processes.
  • Memory Management: Allocation and de-allocation of memory space.
  • File Management: Organizing and tracking files and directories.
  • Device/I/O Management: Managing device drivers and hardware communication.

Q3. What is the Mode Bit? What do the values 0 and 1 represent?

Unit I CO1 | Bloom L2 2 Marks Midterm Score: 9.5

The Mode Bit is a hardware flag used by the OS to differentiate between user-level and system-level execution to protect system integrity.

  • 0: Kernel Mode (System/Supervisor mode) - full access to hardware.
  • 1: User Mode - restricted access.

Q5. Why is DMA (Direct Memory Access) more efficient than Programmed I/O?

Unit I CO1 | Bloom L2 2 Marks Midterm

In Programmed I/O, the CPU must actively monitor and transfer every byte of data between the device and memory, wasting CPU cycles. DMA is more efficient because a dedicated DMA controller handles the bulk data transfer directly to/from memory, allowing the CPU to perform other tasks concurrently. The CPU is only interrupted once the entire block is transferred.

Q6. What is the difference between Hardware Interrupts and Software Interrupts?

Unit I CO1 | Bloom L2 2 Marks Midterm Score: 9.0

Hardware Interrupts are asynchronous signals generated by external hardware devices (e.g., keyboard press, disk I/O completion) to get the CPU's attention. Software Interrupts (Traps) are synchronous signals generated by executing instructions within a program (e.g., system calls, division by zero errors).

Q7. A user program tries to directly access a printer without going through the OS. What will happen, and why?

Unit I CO1 | Bloom L3 2 Marks Midterm

The hardware will generate a trap (exception), and the OS will terminate the program. This happens because accessing I/O devices requires executing privileged instructions, which are strictly forbidden in User Mode (Mode bit = 1) to ensure system security and prevent hardware conflicts.

Q8. While a user is typing a document in MS Word, a timer interrupt occurs in the background. Explain what happens to the CPU's mode bit at that moment.

Unit I CO1 | Bloom L3 2 Marks Midterm

The moment the timer interrupt occurs, the hardware automatically changes the mode bit from 1 (User Mode) to 0 (Kernel Mode). This transfers control to the OS's interrupt handler routine so the OS can safely perform scheduling or background tasks with full hardware privileges.

Q9. A student's program gets stuck in an infinite loop. Which OS mechanism ensures the system does not freeze permanently, and how?

Unit I CO1 | Bloom L2 2 Marks Midterm Score: 9.5

The Timer (Hardware Timer) mechanism prevents permanent freezing. The OS sets a timer to interrupt the CPU after a specific time slice (quantum). When the timer expires, it generates an interrupt that forces the CPU back into Kernel Mode, allowing the OS to regain control and forcefully terminate or preempt the looping program.

Q10. Explain, in brief, why a Monolithic OS structure is fast but hard to maintain, whereas a Microkernel structure is more reliable but comparatively slower.

Unit I CO1 | Bloom L2 2 Marks Midterm Score: 9.0

A Monolithic OS bundles all services (file system, drivers, memory) into a single large kernel, making execution fast (no message passing overhead) but hard to maintain due to tight coupling. A Microkernel keeps only essential services in the kernel and runs the rest in user space; this is reliable (a failed driver won't crash the OS) but slower due to the overhead of inter-process communication (IPC) and frequent mode switching.

Q12. Define Batch Operating System and mention one limitation of this type of system.

Unit I CO1 | Bloom L2 3 Marks Midterm Score: 9.0

A Batch Operating System groups similar jobs into "batches" and executes them sequentially without manual intervention. Users submit jobs to an operator, who batches them and feeds them to the computer.

Limitation: Lack of user interaction. Once a job is submitted, the user must wait for it to finish; if it enters an infinite loop or requires input, the CPU may idle, and debugging is extremely difficult.

Q15. Explain the working of Interrupt-Driven I/O and state why it is more efficient than Programmed I/O.

Unit I CO1 | Bloom L2 3 Marks Midterm Score: 9.0

In Interrupt-Driven I/O, the CPU issues an I/O command to a device controller and immediately resumes executing other tasks. When the device controller finishes reading/writing the data, it sends a hardware interrupt to the CPU. The CPU briefly pauses its current work, processes the data, and resumes.

Efficiency: It eliminates "busy waiting" (polling). The CPU does not waste cycles constantly checking if the device is ready, allowing for true concurrent execution.

Justification: A clustered system consists of multiple independent, fully complete machines (nodes) connected via a network. If one entire machine loses power or hardware fails completely, the other machines in the cluster detect this and take over its workload (High Availability). A multiprocessor system would still fail completely if its shared motherboard or power supply died.

Q20. Justify why modern Operating Systems such as Linux use a Module-Based structure instead of a purely Monolithic or purely Microkernel structure. Support your answer with suitable advantages.

Unit I CO1 | Bloom L3 3 Marks Midterm Score: 9.0

Modern systems use a Hybrid / Loadable Kernel Module (LKM) structure to get the best of both worlds:

  • Performance (Like Monolithic): Modules are loaded directly into the kernel space, meaning there is no slow message-passing overhead like in Microkernels.
  • Flexibility (Like Microkernel): The core kernel remains small. Device drivers and file systems can be loaded dynamically at runtime without rebooting the system or recompiling the entire monolithic kernel.

Q22. Describe the different types of Operating Systems — Batch, Multiprogramming, Time-Sharing, and Real-Time — along with their key features.

Unit I CO1 | Bloom L2 5 Marks Midterm Score: 9.0
  • Batch OS: Jobs with similar needs are batched and executed sequentially by an operator. Feature: No user interaction during execution.
  • Multiprogramming OS: Keeps multiple jobs in memory. When one job waits for I/O, the CPU switches to another. Feature: Maximizes CPU utilization.
  • Time-Sharing OS: An extension of multiprogramming. The CPU switches so rapidly (time-slicing) between tasks that multiple users feel they have dedicated machines. Feature: High interactivity and fairness.
  • Real-Time OS: Processes data instantly within guaranteed deadlines. Feature: Strict timing constraints (used in aviation, medical devices).

Q24. Explain the Dual-Mode operation of an Operating System. How do the Mode Bit and the Timer mechanism work together to protect the system?

Unit I CO1 | Bloom L3 5 Marks Midterm Score: 9.5

Dual-Mode Operation provides hardware-level protection by dividing execution into User Mode (Bit=1) and Kernel Mode (Bit=0). Privileged instructions (like halting the CPU or direct hardware I/O) can only execute in Kernel Mode.

How they work together:
If a malicious user program runs in User Mode, it cannot directly crash the hardware because it lacks privileges. However, it could write an infinite loop to hog the CPU forever. This is where the Timer steps in. The OS configures the hardware timer before switching to User Mode. When the timer hits zero, it triggers an interrupt. The hardware forces the mode bit to 0 (Kernel Mode) and hands control back to the OS, which can then safely kill the malicious looping program.

Q26. Explain the different Operating System structures — Simple, Monolithic, Layered, Microkernel, and Module-Based — highlighting one advantage and one disadvantage of each.

  • Simple (MS-DOS): No clear separation between user/kernel modes. Adv: Fast, low overhead. Disadv: Highly vulnerable to crashes.

Q27. A university wants to set up a computer lab where many students run their programs at the same time, each getting a quick, fair share of CPU time so the system feels interactive to everyone. Suggest a suitable type of Operating System and justify your answer.

The suitable OS is a Time-Sharing Operating System.

It uses CPU scheduling and multiprogramming to provide each user with a small portion of a time-shared computer. The CPU switches from one student's program to the next extremely rapidly (e.g., every 100 milliseconds). Because the switching is so fast, every student gets immediate response times and feels as though they have their own dedicated computer, satisfying the "interactive" and "fair share" requirements.

Q28. A company's server crashes frequently because a bug in a single device driver brings down the entire kernel, since the system uses a Monolithic structure. As an OS designer, propose a better structural approach to avoid this problem, and explain the trade-offs of your proposed solution.

Unit I CO1 | Bloom L4 5 Marks Midterm Score: 9.0

Proposed Solution: A Microkernel Architecture.

By moving the device drivers out of the privileged kernel space and running them as standard user-level processes, a bug or crash in the device driver will only kill that specific process. The Microkernel itself remains isolated and untouched, meaning the server will not crash.

Trade-offs: The primary disadvantage is Performance Overhead. Because the driver is now in user space, communicating with it requires Inter-Process Communication (IPC) and constant context switching between User Mode and Kernel Mode, which slows the system down compared to the direct function calls of a Monolithic kernel.

Q29. Trace a complete scenario: a user clicks 'Print' on a document. Explain, step by step, the roles of the System Call, Device Controller, Interrupt Mechanism, and the switching between User Mode and Kernel Mode in completing this print operation.

  2. A trap occurs, changing the mode bit to 0, switching execution to Kernel Mode.
  3. The OS kernel verifies permissions and sends the print command to the Printer's Device Controller.

Q30. Critically analyze the statement: "Every Operating System structure involves trade-offs; there is no single best structure." Justify this statement with reference to the Monolithic, Microkernel, and Module-Based structures, and explain why modern operating systems like Linux adopt a hybrid, module-based approach for the best balance of performance and design.

Unit I CO1 | Bloom L5 5 Marks Midterm

The statement is completely accurate because structural design always balances performance against maintainability/security.

  • Monolithic: Offers peak performance but sacrifices modularity and stability (one bug crashes everything).
  • Microkernel: Offers peak stability and security (services are isolated) but sacrifices performance (massive IPC overhead).

Why Linux uses a Hybrid/Module approach: Modern OSs like Linux and Windows recognize these extremes are untenable. A Loadable Kernel Module (LKM) approach keeps the core kernel tightly integrated for Monolithic-like performance, while allowing drivers to be dynamically loaded/unloaded like a Microkernel. This achieves the "best of both worlds"—excellent speed without requiring a system reboot every time a new device is connected.

Q32. What is a Process Control Block (PCB)?

Q35. Differentiate between Preemptive and Non-Preemptive Scheduling, giving one example algorithm for each.

Q36. What is the difference between the Ready Queue and the Waiting (Blocked) Queue?

The Ready Queue contains processes that reside in main memory and are fully ready and waiting to be assigned to the CPU. The Waiting Queue contains processes that cannot execute right now because they are waiting for a specific event to occur, such as an I/O completion or receiving a message.

To execute, the User Thread must be mapped onto a Kernel Thread (using models like Many-to-One or Many-to-Many) so the OS scheduler can actually assign it to a physical CPU core.

Q43. List the three types of process schedulers and state the function of each.

  • Medium-Term Scheduler: Swaps processes out of memory to disk and later swaps them back in to relieve memory pressure and improve the process mix.

Q44. Explain the difference between Multiprogramming and Time-Sharing as objectives of process scheduling.

Unit II CO2 | Bloom L3 3 Marks Midterm Score: 9.0
  • Multiprogramming Objective: To maximize CPU utilization. The scheduler ensures the CPU is never idle by switching to a new process only when the current one blocks for I/O.
  • Time-Sharing Objective: To maximize interactivity and response time. The scheduler uses a time quantum to rapidly preempt processes, allowing multiple users to interact with the system simultaneously without noticeable lag.

Q45. Explain why Context Switching is necessary, listing any three situations in which it occurs.

Unit II CO2 | Bloom L2 3 Marks Midterm Score: 9.5

Context Switching is necessary because a single CPU core can only execute one process at a time. To provide the illusion of multitasking, the OS must rapidly swap processes in and out, saving their state so they can resume exactly where they left off.

Situations:

  1. A hardware interrupt occurs (e.g., a key is pressed).
  2. A process's time quantum expires in a Time-Sharing system.
  3. A process makes a blocking System Call (e.g., requesting to read a file).

Q92. What is a Resource Allocation Graph (RAG)?

Unit IV CO4 | Bloom L1 2 Marks End Term Score: 9.0

A Resource Allocation Graph (RAG) is a directed graph $G = (V, E)$ used by an operating system to pictorially track and analyze resource distribution and detect potential deadlocks.

  • Vertices ($V$): Partitioned into two disjoint sets:
    • Process Nodes ($P$): Represented as circles ($P = \{P_1, P_2, \dots, P_n\}$).
    • Resource Nodes ($R$): Represented as rectangles ($R = \{R_1, R_2, \dots, R_m\}$), with dots indicating internal available resource instances.

Q106. Explain why a cycle in a Resource Allocation Graph is a sufficient condition for deadlock with single-instance resources, but only a necessary condition with multiple-instance resources.

Unit IV CO4 | Bloom L3 3 Marks End Term Score: 9.2

The significance of a cycle in a Resource Allocation Graph (RAG) depends on resource instance multiplicity:

  • Single-Instance Resources (Necessary & Sufficient):

    When every resource has only one instance, an edge $R_j \to P_i$ means $P_i$ exclusively possesses the only copy of $R_j$. If a cycle exists ($P_1 \to R_1 \to P_2 \to R_2 \to P_1$), each process in the cycle is waiting for a resource held by another process in the exact same cycle.   • Multiple-Instance Resources (Necessary, but NOT Sufficient):

    A cycle indicates circular dependency among the processes in the cycle. When $P_k$ completes, it releases its instance, which is then allocated to a waiting process in the cycle, successfully breaking the cycle and averting deadlock.

Q110. Explain the Ostrich Algorithm for deadlock handling, and justify why operating systems like Windows and Linux still use it despite its disadvantages.

The Ostrich Algorithm:

The Ostrich Algorithm is a pragmatic deadlock handling approach where the operating system ignores deadlocks entirely—analogous to an ostrich burying its head in the sand—under the assumption that deadlocks occur so rarely that the cost of avoiding or detecting them vastly exceeds the damage caused by their occurrence.

Q111. Explain the four necessary conditions for a deadlock to occur, with one example each.

Unit IV CO4 | Bloom L2 5 Marks End Term Score: 9.7

Deadlock can occur if and only if the following four Coffman conditions hold simultaneously in the system. If even one condition is prevented, deadlock cannot occur:

  1. Mutual Exclusion:

    Explanation: At least one resource must be held in a non-shareable mode, meaning only one process can hold and use the resource at any given moment. Any other process requesting that resource must wait until it is released.

    Example: A physical printer or a dedicated write lock on a database record. If process $P_1$ is printing a document, process $P_2$ cannot simultaneously send data to the same printer without corrupting the output.

  2. Hold and Wait:

    Explanation: A process must currently hold at least one allocated resource while simultaneously waiting to acquire one or more additional resources that are currently being held by other active processes.

    Example: Process $P_1$ opens and holds a DVD burner drive, and while holding it, requests an exclusive lock on an ISO disk image file that is currently being downloaded and held by process $P_2$.

  3. No Preemption:

    Explanation: Resources cannot be forcibly seized or preempted from a process while it is using them. A resource can only be released voluntarily and explicitly by the holding process after it has finished its designated execution.

    Example: The OS cannot arbitrarily yank a tape drive away from a running backup process halfway through writing an archive without corrupting the data stream.

  4. Circular Wait:

    Explanation: A closed directed chain of processes $\{P_0, P_1, \dots, P_n\}$ exists such that $P_0$ is waiting for a resource held by $P_1$, $P_1$ is waiting for a resource held by $P_2$, and $P_n$ is waiting for a resource held by $P_0$.

    Example: Process $P_1$ holds Resource $R_1$ and requests $R_2$, while Process $P_2$ holds $R_2$ and requests $R_1$. Neither process can proceed, producing an intractable mutual blockage.

Q112. Explain the three methods of deadlock recovery: Process Termination, Resource Preemption, and Process Rollback.

Unit IV CO4 | Bloom L2 5 Marks End Term Score: 9.2

Once a deadlock has been detected by the operating system, the deadlock cycle must be broken using one of three primary recovery techniques:

  1. Process Termination:

    Involves terminating one or more processes to eliminate cyclic wait dependencies:

    • Abort all deadlocked processes: The most drastic approach. Completely breaks the deadlock immediately, but discards all partial computations, resulting in high economic and computational cost.
    • Abort one process at a time: The OS terminates one process and reruns the deadlock detection algorithm, repeating until the cycle is eliminated. Victim selection criteria include: process priority, execution time elapsed, remaining time to complete, resources held, and whether the process is interactive or batch.
  2. Resource Preemption:

    Involves forcibly taking away resources from some processes and allocating them to other deadlocked processes until the deadlock cycle is resolved. Three critical issues must be addressed:

    • Selecting a Victim: Determine which process holds resources that can be preempted with minimum overall cost penalty.
    • Rollback: Because a resource was preempted, the victim process cannot proceed normally. The OS must roll back the victim process to a safe checkpoint state and restart it from that point.
    • Starvation: If the same process is repeatedly chosen as the lowest-cost victim, it may never complete. The OS prevents this by incorporating the number of rollbacks into the process's priority calculation (aging).
  3. Process Rollback:

    The operating system periodically checkpoints the state of executing processes (register values, memory images, file locks). When deadlock is detected, the OS rolls back a selected process to its last saved checkpoint rather than killing it entirely, frees its recently acquired resources to resolve the deadlock, and reschedules it later.

Q113. Explain Paging in detail, including the concepts of pages, frames, and the page table.

Unit IV CO4 | Bloom L2 5 Marks End Term Score: 9.6

Paging is a non-contiguous memory management hardware scheme that permits the physical address space of a process to be non-contiguous, completely eliminating external fragmentation.

  1. Core Architectural Concepts:
    • Pages: The logical address space of a process is divided into equal, fixed-size blocks called pages (typically $4\text{ KB} = 2^{12}$ bytes).
    • Frames: Physical main memory (RAM) is divided into fixed-size blocks of the exact same size called frames.
    • Page Table: A dedicated hardware/OS data structure maintained per process that maps each logical page number ($p$) to its corresponding physical frame number ($f$).
  2. Address Translation Mechanics:

    A logical address generated by the CPU is mathematically partitioned into two parts:

    • Page Number ($p$): Used as an index into the page table to retrieve the base frame number ($f$).
    • Page Offset ($d$): Defines the displacement within the page. Combined directly with the frame number to access the physical byte.
    $$\text{Logical Address} = (p, d) \xrightarrow{\text{Page Table Mapping}} \text{Physical Address} = (f, d) = (f \times \text{Page Size}) + d$$
  3. Evaluation:
    • Advantages: Completely eliminates external fragmentation; simplifies memory allocation (any free frame can be allocated to any process); supports memory protection and virtual memory.
    • Disadvantages: Suffers from internal fragmentation on the last page of a process (averaging $\frac{1}{2}$ page per process); requires page table storage in RAM and translation overhead (mitigated by Translation Lookaside Buffers - TLBs).

Q120. Critically analyze why Deadlock Avoidance (Banker's Algorithm) is theoretically stronger than Deadlock Prevention but is rarely used in real operating systems, with reference to the assumption that maximum resource needs must be known in advance.

Critical Analysis of Deadlock Avoidance vs. Deadlock Prevention in Practical Operating Systems:

  1. Theoretical Superiority of Avoidance:

    Theoretically, Deadlock Avoidance (e.g., Banker's Algorithm) is vastly superior to Deadlock Prevention because it does not impose artificial, restrictive constraints on resource usage (such as holding only one resource, releasing all resources, or enforcing rigid linear acquisition order).   2. The Fatal Assumption: Advance Knowledge of Maximum Resource Needs
    • The Banker's Algorithm requires every process to declare its maximum resource claim a priori before execution starts.
    • In modern general-purpose operating systems (Linux, Windows, macOS), applications are inherently dynamic, event-driven, and user-interactive.   3. Static Process and Resource Assumptions:

    The Banker's Algorithm assumes a fixed number of processes ($N$) and a fixed number of resources ($M$). In real OS environments, processes constantly fork, spawn threads, and terminate, while peripheral resources (printers, USB storage, network adapters) are hot-plugged and unplugged dynamically.

    Running the safety algorithm ($O(M \times N^2)$) on every single resource request or memory frame allocation introduces prohibitive CPU latency bottlenecks on multi-core systems running thousands of threads.

  5. Pragmatic Conclusion:

    Because real applications cannot accurately pre-declare maximum demands, general-purpose operating systems abandon avoidance in favor of the Ostrich Algorithm combined with lightweight user-space timeouts, lock ranking (prevention), or manual process termination via task managers.

Q131. Explain the steps involved in handling a Page Fault.

Unit V CO5 | Bloom L2 3 Marks End Term Score: 9.7

When a process references an invalid page table entry, the OS handles the page fault through the following systematic sequence:

  1. Trap to OS: The MMU detects an invalid bit reference and triggers an internal hardware trap to the OS kernel.
  2. Validate Reference: The OS saves user registers and checks the Process Control Block (PCB). If the address is invalid, the process is terminated (Segmentation Fault); otherwise, it proceeds with paging.
  3. Locate on Backing Store: The OS determines the physical disk address of the missing page on the swap device.
  4. Allocate Physical Frame: The OS finds a free frame from the free-frame list. If none are free, a page replacement algorithm (e.g., LRU) selects a victim frame, writing it back to disk if modified (dirty bit set).
  5. Disk I/O: A disk read request is scheduled to fetch the requested page into the selected frame; the faulting process enters the I/O wait queue.
  6. Update Page Table & Restart: Upon I/O completion interrupt, the OS updates the page table (sets frame number, valid bit to 1), restores process registers, and restarts the instruction.

Q142. Explain Thrashing — its causes and the methods used to prevent it.

Unit V CO5 | Bloom L2 5 Marks End Term Score: 9.7

Thrashing is a pathological system condition in virtual memory management where an operating system spends virtually all its resources servicing page faults (swapping pages between memory and disk) rather than executing productive process instructions, causing CPU utilization to plummet toward zero.

Primary Causes of Thrashing:

  • Overcommitment of Multiprogramming: When the OS scheduler admits too many processes into memory, the number of frames allocated to each process drops below its minimum working set.
  • Global Page Replacement Policy: When process $A$ page faults, it can steal a frame from process $B$. Process $B$ immediately page faults and steals a frame from process $C$, propagating a cascading chain reaction of page faults across the entire system.
  • Violation of Locality: If a process transitions to a new execution phase where its working set demand exceeds its allocated frames, frequent page faults saturate the swap disk queue.

Methods to Prevent Thrashing:

  1. Working Set Model (Peter Denning):
    • Defines the working set $W(t, \Delta)$ as the set of pages referenced in the most recent $\Delta$ time units.
    • The OS computes working set size $\text{WSS}_i$ for each process and total frame demand $D = \sum \text{WSS}_i$.
    • If $D > m$ (total physical frames), thrashing is imminent. The OS suspends (swaps out) one or more processes and reallocates their frames to active processes until $D \le m$.
  2. Page Fault Frequency (PFF) Strategy:
    • Establishes upper ($TR_{\text{high}}$) and lower ($TR_{\text{low}}$) acceptable page fault rate boundaries.
    • If a process's page fault rate exceeds $TR_{\text{high}}$, it is allocated additional frames. If its rate falls below $TR_{\text{low}}$, excess frames are reclaimed.
    • If page faults remain high across processes and no free frames exist, the OS swaps out an entire process to free up physical memory.
  3. Local Page Replacement Policy:
    • Forces each process to select replacement frames strictly from its own allocated frame pool, isolating thrashing to offending processes and preventing system-wide collapse.

Q145. Explain Discretionary Access Control (DAC) and Mandatory Access Control (MAC), comparing their working, security level, and typical use cases.

Unit V CO5 | Bloom L4 5 Marks End Term Score: 9.2

Access control models define how an operating system regulates subject (user/process) access to objects (files/devices):

  1. Discretionary Access Control (DAC):
    • Working Principle: The creator/owner of a file has complete discretion over permission assignment. The owner explicitly defines access privileges (Read, Write, Execute) for specific users or groups via Access Control Lists (ACLs) or permission bits (e.g., POSIX chmod/chown).
    • Security Level: Moderate to Low. DAC cannot prevent transitive data leakage or Trojan horses: if User A authorizes User B to read a secret file, User B can copy the contents into a new file and grant read access to everyone.
    • Typical Use Cases: General-purpose commercial operating systems (standard Linux, macOS, Microsoft Windows NTFS).
  2. Mandatory Access Control (MAC):
    • Working Principle: Access decisions are centrally enforced by the operating system kernel based on fixed, system-wide security policies. Every subject is assigned a clearance label, and every object is assigned a classification label (e.g., Unclassified, Confidential, Secret, Top Secret). Users cannot alter or delegate permissions.
    • Security Rules: Enforces mathematical security models such as the Bell-LaPadula model:
      • Simple Security Property (No Read Up): A subject at a lower clearance level cannot read an object at a higher classification level.
      • $\star$-Property (No Write Down): A subject at a higher clearance level cannot write/leak information into an object at a lower classification level.
    • Security Level: High. Immune to Trojan horses and unauthorized delegation.
    • Typical Use Cases: Military, defense systems, intelligence agencies, high-assurance banking, and SELinux / TrustedBSD environments.

Q148. Using the Working Set Model, a newly started process has not yet built up its working set and is experiencing excessive page faults. Explain why Minimum Frame Allocation would help this process, and what happens if the OS fails to provide it.

Unit V CO5 | Bloom L4 5 Marks End Term

The Cold-Start Dilemma:
When a process begins execution, its working set window contains zero resident pages. Every initial memory reference triggers a cold-start page fault. Until the process populates its working set $W(t, \Delta)$ with essential code segments, stack frames, and globals, it experiences high fault frequencies.

Why Minimum Frame Allocation Helps:

  • Instruction Completion Guarantee: CPU machine architectures require that certain multi-byte or complex instructions execute atomically. For example, an indirect addressing instruction like MOVE (R1)+, (R2)+ may require up to 6 distinct frames simultaneously: the instruction page, indirect source address page, actual source page, indirect destination address page, destination page, and stack pointer.
  • Preventing Intra-Instruction Thrashing: Minimum frame allocation guarantees that an executing instruction can hold all required pages in physical memory simultaneously, ensuring execution progresses without getting trapped in a page-fault cycle mid-instruction.

What Happens if the OS Fails to Provide Minimum Frames:

  1. Infinite Trap Loops: If a process receives fewer frames than required by a single instruction, it will fetch page $A$, fault on page $B$, evict page $A$ to load $B$, restart the instruction, fault on page $A$ again, and evict page $B$—trapping the CPU in an endless, unresolvable page-fault loop.
  2. Severe Process Starvation: The process can never complete a single clock cycle of productive work, starving indefinitely in the wait queue.
  3. Immediate Thrashing: The CPU scheduler repeatedly cycles through unexecutable threads, driving paging disk queues to $100\%$ saturation.

Q150. Critically analyze the trade-off between Global Replacement and Local Replacement frame allocation policies, explaining why Global Replacement can give better overall throughput but cause unpredictable performance for individual processes, using the concept of Thrashing to support your answer.

Unit V CO5 | Bloom L5 5 Marks End Term

The conflict between Global Replacement and Local Replacement represents a classic operating systems trade-off between aggregate system throughput and individual process execution predictability:

1. Why Global Replacement Achieves Higher Overall Throughput:

  • Dynamic Resource Adaptation: Processes have constantly shifting working set sizes. Global replacement dynamically shifts memory frames from idle or sleeping processes to active, compute-heavy processes.
  • Minimized Unused Frame Waste: No physical frames remain locked or underutilized in static process allocations. This optimal utilization maximizes overall system throughput under light-to-moderate workloads.

2. Why Global Replacement Causes Unpredictable Performance & Cascading Thrashing:

  • Loss of Per-Process Runtime Isolation: Under global replacement, a process's paging behavior is not independent—it depends on the memory access patterns of every other active process in the system. A process may run in 5 seconds in one instance and 5 minutes in another.
  • Cascading Thrashing Contagion: If one rogue or memory-intensive process starts thrashing, it continuously page faults and preempts frames from other well-behaved processes. The victim processes, now stripped of their working sets, immediately begin page faulting as well and steal frames from others.
  • System-Wide Collapse: This triggers a domino effect of page faults across all processes, saturating the paging disk queues and driving CPU utilization to near zero.

3. The Local Replacement Trade-off:

  • Containment of Thrashing: Local replacement restricts victim selection strictly to the faulting process's own allocated frame pool. If a process thrashes, the blast radius is strictly contained to that single process, ensuring other processes continue executing with predictable runtimes.
  • Drawback: It cannot reclaim unreferenced frames from processes that have completed a phase, leading to lower overall memory efficiency and throughput.

Conclusion: Modern operating systems employ hybrid strategies (such as PFF or the Working Set Model with local replacement fallbacks) to capture the throughput benefits of global allocation while enforcing dynamic quotas that prevent catastrophic thrashing contagion.
