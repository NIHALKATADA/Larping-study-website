Unit I: Introduction & Sorting

An algorithm

An algorithm is a step-by-step procedure or set of rules to be followed in calculations or other problem-solving operations. Characteristics:

  • Finiteness: Must terminate after a finite number of steps.
  • Definiteness: Each step must be precisely defined.
  • Input: Has zero or more inputs.
  • Output: Produces one or more outputs.
  • Effectiveness: Operations must be basic enough to be done exactly and in finite time.
While An algorithm gives us the theoretical background, Pseudocode provides the next layer of complexity.

Pseudocode

Pseudocode is an informal, high-level description of the operating principle of a computer program or algorithm. Advantages:

  • Easier for humans to read and understand compared to actual code.
  • Independent of any specific programming language, making it versatile.
Building on our understanding of Pseudocode, let's dive into Time complexity and space complexity with one example.

Time complexity and space complexity with one example

Time Complexity: The amount of time an algorithm takes to run as a function of the length of the input. Space Complexity: The amount of memory an algorithm requires to run as a function of the length of the input.

Example: Mergesort has a time complexity of O(n log n) and space complexity of O(n), whereas Bubble sort has time complexity O(n^2) but space complexity O(1).

While Time complexity and space complexity with one example gives us the theoretical background, Big-O notation provides the next layer of complexity.

Big-O notation

Big-O notation is a mathematical notation that describes the limiting behavior of a function when the argument tends towards a particular value or infinity. In computer science, it is used to classify algorithms according to how their run time or space requirements grow as the input size grows. It describes the upper bound of the complexity.

Building on our understanding of Big-O notation, let's dive into Best-case, worst-case, and average-case analysis.

Best-case, worst-case, and average-case analysis

  • Best-case: The minimum time required for program execution for any input of size n.
  • Worst-case: The maximum time required for program execution for any input of size n. (Provides an upper bound).
  • Average-case: The expected time required for program execution over all possible inputs of size n.
While Best-case, worst-case, and average-case analysis gives us the theoretical background, Asymptotic analysis provides the next layer of complexity.

Asymptotic analysis

Asymptotic analysis evaluates the performance of an algorithm in terms of input size (n) as it approaches infinity. It is preferred because execution time depends on hardware, compiler, and OS, whereas asymptotic analysis provides a machine-independent way to compare algorithms' efficiency.

Having established the core principles of Asymptotic analysis, we now turn our attention to Amortized analysis.

Amortized analysis

Amortized analysis calculates the average time taken per operation, over a sequence of operations, guaranteeing the average performance even if a single operation is expensive.

Aggregate method: It computes the total time T(n) for a sequence of n operations and sets the amortized cost per operation to T(n)/n.

Unit II: Divide & Conquer

Algorithm correctness

Algorithm Correctness: An algorithm is correct if, for every valid input, it halts and produces the correct output as defined by its specifications.

  • Partial Correctness: If the algorithm halts, it produces the correct output (but it might not halt). Example: A while(true) loop that searches for an element and breaks when found. If the element isn't there, it might loop forever.
  • Total Correctness: The algorithm is guaranteed to halt, and when it halts, it produces the correct output. Example: A standard for-loop based linear search that scans an array from start to end and returns true/false.
While Algorithm correctness gives us the theoretical background, A loop invariant provides the next layer of complexity.

A loop invariant

A loop invariant is a condition or property that is true before and after each iteration of a loop. It is used to prove the correctness of loop structures.

  1. Initialization: The invariant must be true before the first iteration of the loop.
  2. Maintenance: If it is true before an iteration of the loop, it remains true before the next iteration.
  3. Termination: When the loop terminates, the invariant gives us a useful property that helps show the algorithm is correct.
Transitioning from A loop invariant, we now examine How loop invariants can be used to prove the correctness of a sorting algorithm, which builds upon these foundational rules.

How loop invariants can be used to prove the correctness of a sorting algorithm

In sorting algorithms like Insertion Sort, a loop invariant can be defined as: 'At the start of each iteration i, the subarray A[0...i-1] consists of the elements originally in A[0...i-1], but in sorted order.'

  • Initialization: For i=1, A[0] is just a single element, which is trivially sorted.
  • Maintenance: During iteration i, the algorithm inserts A[i] into its correct position in A[0...i-1], making A[0...i] sorted.
  • Termination: The loop ends when i = n. The invariant states that A[0...n-1] is sorted, which means the entire array is sorted, proving correctness.

Difference between BUILD-MAX-HEAP and MAX-HEAPIFY

MAX-HEAPIFY: Maintains the max-heap property for a given node, assuming its left and right subtrees are already max heaps. It has a time complexity of O(log n).

BUILD-MAX-HEAP: Constructs a max heap from an unordered array by calling MAX-HEAPIFY in a bottom-up manner on all non-leaf nodes. It has a time complexity of O(n).

A heap

A Heap is a specialized tree-based data structure that satisfies the heap property, typically implemented as an almost complete binary tree.

  • Max Heap: The value of each node is greater than or equal to the values of its children. The largest element is at the root. Example: [100, 19, 36]
  • Min Heap: The value of each node is less than or equal to the values of its children. The smallest element is at the root. Example: [1, 2, 3]

Unit III: Dynamic Programming

Divide and Conquer paradigm

Divide and Conquer Paradigm

The Divide and Conquer paradigm is an algorithmic design strategy that solves a problem by recursively breaking it down into two or more sub-problems of the same or related type, until these become simple enough to be solved directly. The solutions to the sub-problems are then combined to give a solution to the original problem.

It consists of three basic steps:

  • Divide: Break the given problem into smaller sub-problems.
  • Conquer: Recursively solve these sub-problems. If the sub-problem size is small enough, solve it directly (base case).
  • Combine: Merge the solutions of the sub-problems to form the solution of the original problem.
Example: Merge Sort

In Merge Sort:

  • Divide: Divide the unsorted array of size n into two sub-arrays of size n/2.
  • Conquer: Recursively sort the two sub-arrays using Merge Sort.
  • Combine: Merge the two sorted sub-arrays into a single sorted array.
To fully appreciate Divide, conquer, and combine steps in a Divide and Conquer algorithm, we must apply what we just learned about Divide and Conquer paradigm.

Divide, conquer, and combine steps in a Divide and Conquer algorithm

The three main steps of the Divide and Conquer strategy are:

  • Divide: This step involves breaking the original problem into a set of smaller sub-problems. The sub-problems should represent a smaller instance of the same original problem.
  • Conquer: This step involves solving the sub-problems recursively. If the sub-problem is small enough (the base case), it is solved directly without further division.
  • Combine: This step involves taking the solutions to the sub-problems and merging them together to formulate the solution to the original problem.
Having established the core principles of Divide, conquer, and combine steps in a Divide and Conquer algorithm, we now turn our attention to General structure of a Divide and Conquer algorithm.

General structure of a Divide and Conquer algorithm

General Structure

The general structure of a Divide and Conquer algorithm can be represented recursively:

Algorithm DAndC(P)
{
    if Small(P) then
        return S(P); // Solve directly
    else
    {
        Divide P into smaller instances P1, P2, ..., Pk, k ≥ 1;
        Apply DAndC to each of these subproblems;
        return Combine(DAndC(P1), DAndC(P2), ..., DAndC(Pk));
    }
}
Difference from Iterative Algorithms
  • Control Flow: Divide and Conquer algorithms rely heavily on recursion (functions calling themselves), whereas iterative algorithms use loops (for, while) to repeat tasks.
  • State Management: In recursion, state is maintained implicitly by the call stack. In iteration, variables explicitly hold state (like loop counters).
  • Approach: Divide and conquer works top-down (breaking large to small), while dynamic programming or iterative methods can work bottom-up (solving small to build large).
Moving forward from General structure of a Divide and Conquer algorithm, let's break down the mechanics of Identify whether the following algorithms use the Divide and Conquer technique.

Identify whether the following algorithms use the Divide and Conquer technique

  • Binary Search: Yes. It divides the array into two halves, compares the target with the middle element, and recursively conquers only one of the halves. The combine step is trivial (returning the index).
  • Merge Sort: Yes. It divides the array into two halves, recursively sorts each half (conquer), and then merges the two sorted halves (combine).
  • Quick Sort: Yes. It chooses a pivot to divide the array into two partitions (smaller than pivot and greater than pivot), recursively sorts the partitions (conquer). Combine is trivial as sorting is done in place.
  • Bubble Sort: No. It is an iterative comparison-based algorithm that repeatedly swaps adjacent elements if they are in the wrong order. It does not divide the problem into smaller subproblems or use recursion.
Transitioning from Identify whether the following algorithms use the Divide and Conquer technique, we now examine Advantages and limitations of the Divide and Conquer approach, which builds upon these foundational rules.

Advantages and limitations of the Divide and Conquer approach

Advantages
  • Solving Complex Problems: Makes solving conceptually difficult problems easier by breaking them down into simpler, smaller sub-problems.
  • Parallelism: Sub-problems are independent and can often be executed in parallel on multi-core processors.
  • Memory Access Efficiency: Can be designed to optimize cache usage, as smaller sub-problems fit easily into the CPU cache.
  • Efficiency: Often yields algorithms with faster time complexities, e.g., reducing O(n²) to O(n log n) in sorting.
Limitations
  • Overhead: The recursion and function call stack overhead can make them slower for small inputs compared to simple iterative approaches.
  • Space Complexity: Deep recursion trees can lead to stack overflow or require excessive auxiliary space.
  • Repeated Subproblems: If not careful, overlapping subproblems can be solved multiple times, leading to inefficiencies (better handled by Dynamic Programming).

A recurrence relation

A recurrence relation is an equation or inequality that describes a mathematical function in terms of its value on smaller inputs.

Role in Analyzing Time Complexity:

When an algorithm contains a recursive call, its running time can be described by a recurrence relation. For example, in Merge Sort, solving a problem of size n involves two subproblems of size n/2, and merging takes linear time O(n). This gives the recurrence:

T(n) = 2T(n/2) + O(n)

By solving this recurrence relation (using methods like the Substitution Method, Recursion Tree Method, or Master Theorem), we can express the time complexity of the algorithm in Big-O notation (e.g., O(n log n)).

Solve the following recurrence using the substitution method

Recurrence: T(n) = 2T(n/2) + n

Guess: T(n) = O(n log n). We need to prove that T(n) ≤ c · n log n for some constant c > 0.

Proof by induction:

  • Assume the bound holds for n/2, i.e., T(n/2) ≤ c · (n/2) log(n/2).
  • Substitute this into the recurrence:
    T(n) ≤ 2 · [c · (n/2) log(n/2)] + n
    T(n) ≤ c · n log(n/2) + n
    T(n) ≤ c · n(log n - log 2) + n
    T(n) ≤ c · n log n - c · n + n
  • We want T(n) ≤ c · n log n. This holds true if:
    c · n log n - c · n + n ≤ c · n log n
    -c · n + n ≤ 0
    c ≥ 1

Since we can choose c ≥ 1, the guess is correct.

Result: T(n) = O(n log n)

Why Sorting is Required: Binary search fundamentally relies on the ordering of elements. It compares the target value to the middle element and mathematically eliminates half of the remaining search space based on that comparison. If target < mid, it knows the target must be in the left half, because all elements in the left half are smaller than the middle element.

If Applied to an Unsorted Array: The logic breaks down. Comparing the target to the middle element gives no reliable information about where the target might be located in the rest of the array. The search might discard the half that actually contains the target, leading to a false negative (returning "not found" even when the element exists).

How the Divide and Conquer technique can be used to find the maximum and minimum elements of an array

The Divide and Conquer Max-Min algorithm finds both the maximum and minimum elements simultaneously by recursively breaking the array into halves.

  • Divide: Split the array into two halves.
  • Conquer: Recursively find the (max, min) pair for the left half and the (max, min) pair for the right half.
    • Base Cases:
      • If the subarray has 1 element, return it as both max and min.
      • If the subarray has 2 elements, compare them and return the larger as max and the smaller as min.
  • Combine: Compare the max of the left half with the max of the right half to get the overall max. Compare the min of the left half with the min of the right half to get the overall min.

Best-case, average-case, and worst-case time complexity of Quick Sort

Best Case: O(n log n)

Occurs when the pivot chosen at each step divides the array into two roughly equal halves. The recursion tree has a depth of log(n) and partitioning at each level takes O(n) time. Recurrence: T(n) = 2T(n/2) + O(n)

Average Case: O(n log n)

Occurs when the pivot randomly divides the array into proportional splits (e.g., 9-to-1 split or 3-to-1 split). Even an unbalanced split like 99-to-1 results in an O(n log n) running time, as the depth of the tree is bounded by a logarithmic function.

Worst Case: O(n²)

Occurs when the pivot is consistently the smallest or largest element, leading to completely unbalanced partitions (one sub-array of size n-1, and one of size 0). This creates a skewed recursion tree of depth n. Example: sorting an already sorted array when the first or last element is chosen as the pivot. Recurrence: T(n) = T(n-1) + O(n)

How the Divide and Conquer technique can be used for multiplication of large integers

When integers are very large (e.g., hundreds of digits in cryptography), standard multiplication (O(n²)) is too slow. The Divide and Conquer technique (Karatsuba algorithm) speeds this up.

Process:

  1. Divide: Split each n-digit number into two halves (high and low parts).
    Example: X = A*10^(n/2) + B and Y = C*10^(n/2) + D
  2. Standard Divide and Conquer: Compute four partial products (AC, AD, BC, BD). This yields T(n) = 4T(n/2) + O(n) → O(n²).
  3. Karatsuba Optimization: Compute only three products recursively:
    • P1 = A * C
    • P2 = B * D
    • P3 = (A + B) * (C + D)
    The middle term (AD + BC) is derived as P3 - P1 - P2.
  4. Conquer and Combine: This reduces the recurrence to T(n) = 3T(n/2) + O(n), improving the time complexity to O(nlog23) ≈ O(n1.585).
Building on our understanding of How the Divide and Conquer technique can be used for multiplication of large integers, let's dive into Is merge sort a stable sorting algorithm.

Is merge sort a stable sorting algorithm

Yes, Merge Sort is a stable sorting algorithm.

Explanation: A sorting algorithm is stable if it preserves the relative order of equal elements. In Merge Sort, stability is maintained during the merge step. When combining two sorted sub-arrays, if elements are equal, the element from the left sub-array (which appeared earlier in the original array) is explicitly chosen to be placed into the merged array first. By doing this, the original relative ordering of equal elements is preserved.

Moving forward from Is merge sort a stable sorting algorithm, let's break down the mechanics of When would you select merge sort instead of quick sort.

When would you select merge sort instead of quick sort

Merge Sort is preferred over Quick Sort in the following scenarios:

  • Stability is Required: Merge Sort is inherently stable, whereas Quick Sort is not.
  • Worst-Case Guarantees: Merge Sort guarantees O(n log n) time complexity in all cases. Quick Sort can degrade to O(n²) in the worst case (e.g., already sorted arrays with bad pivot choice).
  • Sorting Linked Lists: Merge Sort performs excellently on linked lists because elements don't need contiguous memory access for random swaps (unlike Quick Sort). The O(n) auxiliary space requirement of Merge Sort is also reduced to O(1) for linked lists.
  • External Sorting: When the dataset is too large to fit in RAM and resides on disk, Merge Sort's predictable sequential access patterns make it the preferred choice.
