Unit I: Introduction, ER Modeling & Normalization

Database Architecture & Abstraction

Core concepts of database systems over traditional file systems.

  • DBMS Advantages: Eliminates redundancy, ensures consistency, provides security.
  • Three-Level Architecture: External (views), Conceptual (logical structure), Internal (physical storage).
  • Data Independence: Ability to change schema at one level without affecting the higher level.
Now that we have a solid grasp of Database Architecture & Abstraction, the natural next step is to explore Data Models & Keys.

Data Models & Keys

Foundational principles of the relational model and data integrity.

  • Relational Model: Organizes data into 2D tables (relations) with flexibility and data independence.
  • Keys: Super key (any unique combo), Candidate key (minimal super key), Primary key (main identifier), Foreign key (referential link).
  • Integrity Constraints: Domain, Key, Entity (PK not null), Referential (FK must match PK).
Having established the core principles of Data Models & Keys, we now turn our attention to Entity-Relationship (ER) Basics.

Entity-Relationship (ER) Basics

Visual representation of real-world objects and their associations.

  • Entities & Sets: Objects (rectangles) and collections of similar objects.
  • Attributes: Properties (ellipses) including simple, composite, derived, multivalued, and key.
  • Relationships: Associations between entities (diamonds) like 1:1, 1:N, M:N.
  • Weak Entities: Lack a primary key, depend on an identifying owner.
Moving forward from Entity-Relationship (ER) Basics, let's break down the mechanics of Advanced ER Concepts.

Advanced ER Concepts

Extended features for complex data modeling in E-R diagrams.

  • Generalization/Specialization: Bottom-up grouping vs Top-down subclassing (Disjoint or Overlapping).
  • Aggregation: Treating a relationship as an entity for higher-level associations.
  • Participation: Total (mandatory, double line) vs Partial (optional, single line).
  • Degrees: Unary, Binary, and Ternary relationships.
Now that we have a solid grasp of Advanced ER Concepts, the natural next step is to explore Functional Dependencies & Normal Form....

Functional Dependencies & Normal Forms (1NF-BCNF)

Process of organizing data to reduce redundancy and anomalies.

  • Anomalies: Resolves insertion, update, and deletion issues.
  • 1NF: Ensures atomic, indivisible values in all columns.
  • 2NF: Eliminates partial dependencies on the primary key.
  • 3NF: Eliminates transitive dependencies between non-key attributes.
  • BCNF: Stricter 3NF where every determinant must be a super key.
Having established the core principles of Functional Dependencies & Normal Form..., we now turn our attention to Advanced Normalization & Decomposition.

Advanced Normalization & Decomposition

Higher normal forms and rules for safely splitting tables.

  • 4NF & 5NF: Eliminates multi-valued dependencies and handles join dependencies.
  • Decomposition: Breaking a large table into smaller, manageable tables.
  • Lossless Join: Ensures no data is lost or spuriously created when re-joining tables.
  • Dependency Preservation: All original functional dependencies must be maintainable in decomposed tables.

Unit II: Relational Algebra & SQL Basics

Relational Algebra & Calculus

Theoretical query languages underlying modern relational databases.

  • Basic Operations: Select, Project, Union, Set Difference, Cartesian Product.
  • Derived Operations: Joins, Intersection, Division.
  • Relational Calculus: Non-procedural queries via Tuple (TRC) and Domain (DRC) calculus.
Now that we have a solid grasp of Relational Algebra & Calculus, the natural next step is to explore SQL Fundamentals & Commands.

SQL Fundamentals & Commands

Categorization of SQL statements based on their functionality.

  • DDL (Data Definition Language): CREATE, ALTER, DROP, TRUNCATE to define structures.
  • DML (Data Manipulation Language): INSERT, UPDATE, DELETE, SELECT to manage data.
  • DCL (Data Control Language): GRANT, REVOKE for security and permissions.
  • TCL (Transaction Control): COMMIT, ROLLBACK, SAVEPOINT for state management.
Having established the core principles of SQL Fundamentals & Commands, we now turn our attention to SQL Joins.

SQL Joins

Methods to combine rows from multiple tables based on related columns.

  • Inner Joins: Returns rows with matching values in both tables (Equi vs Natural).
  • Outer Joins: Includes unmatched rows from Left, Right, or Full tables.
  • Self Join: Joining a table to itself for hierarchical data.
  • Cross Join: Returns the Cartesian product of both tables.
Building on our understanding of SQL Joins, let's dive into Grouping & Aggregation.

Grouping & Aggregation

Techniques for summarizing and sorting dataset results.

  • Aggregate Functions: COUNT, SUM, AVG, MAX, MIN for calculations across rows.
  • GROUP BY: Groups rows sharing a property so aggregate functions can be applied to each group.
  • HAVING Clause: Filters groups created by GROUP BY (unlike WHERE which filters rows).
  • ORDER BY: Sorts the final result set in ascending or descending order.
Transitioning from Grouping & Aggregation, we now examine Subqueries & Nested Queries, which builds upon these foundational rules.

Subqueries & Nested Queries

Embedding one query inside another for complex filtering.

  • Simple Subquery: Executes once and passes the result to the outer query.
  • Correlated Subquery: Executes repeatedly, once for each row evaluated by the outer query.
  • Operators: Utilizes IN, EXISTS, ANY, and ALL for set comparisons.
While Subqueries & Nested Queries gives us the theoretical background, SQL Views provides the next layer of complexity.

SQL Views

Virtual tables derived from the result of a SQL query.

  • Simple Views: Based on a single table, easily updatable.
  • Materialized Views: Physically stores the result set for faster retrieval of complex queries.
  • Advantages: Enhances security, simplifies complex queries, provides data abstraction.

Unit III: Advanced SQL, Constraints & Transactions

Advanced DDL & Constraints

Rules to enforce data integrity and manage table structures dynamically.

  • Constraints: NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK.
  • Levels: Defined at the column-level or table-level (required for composite keys).
  • ALTER Operations: Adding/modifying columns, changing data types, dropping constraints.
  • Table Management: Renaming tables, duplicating structures with CREATE TABLE AS SELECT.
Now that we have a solid grasp of Advanced DDL & Constraints, the natural next step is to explore SQL Built-in Functions.

SQL Built-in Functions

Functions for manipulating numeric, string, and temporal data.

  • Numeric Functions: ROUND, TRUNCATE, CEIL, FLOOR, MOD, POWER, SQRT, ABS.
  • String Functions: CONCAT, UPPER/LOWER, LENGTH, SUBSTRING, TRIM, REPLACE.
  • Date Functions: CURDATE, DATEDIFF, DATE_ADD, DATE_SUB, DATE_FORMAT.
With SQL Built-in Functions in mind, we can see why Set Operations becomes crucial in this context.

Set Operations

Combining results from multiple SELECT statements.

  • UNION: Combines results and removes duplicates.
  • UNION ALL: Combines results while retaining duplicates.
  • INTERSECT: Returns only rows common to both result sets.
  • MINUS / EXCEPT: Returns rows from the first query that are not in the second.
  • Condition: Queries must have the same number of columns and compatible data types.
Moving forward from Set Operations, let's break down the mechanics of Conditional Expressions.

Conditional Expressions

Adding procedural logic directly within SQL queries.

  • CASE Statement: Provides IF-THEN-ELSE logic within SELECT lists.
  • IF Function: Shorthand for simple condition checking.
  • COALESCE: Returns the first non-NULL value in a list (useful for default values).
With Conditional Expressions in mind, we can see why Transaction Management becomes crucial in this context.

Transaction Management

Ensuring reliable processing of database operations.

  • ACID Properties: Atomicity, Consistency, Isolation, Durability for reliable transactions.
  • COMMIT: Permanently saves all changes made during the current transaction.
  • ROLLBACK: Undoes changes made since the last commit.
  • SAVEPOINT: Sets a marker to rollback a portion of a transaction rather than the whole thing.
To fully appreciate PL/SQL Concepts, we must apply what we just learned about Transaction Management.

PL/SQL Concepts

Procedural extensions and automated database logic.

  • Stored Procedures: Precompiled SQL code blocks that can be reused and accept parameters.
  • Triggers: Code that automatically executes BEFORE or AFTER a specific DML event.
  • Cursors: Mechanism to process multiple rows returned by a query, one by one.
  • Exception Handling: Using DECLARE HANDLER and SIGNAL to manage errors gracefully.
